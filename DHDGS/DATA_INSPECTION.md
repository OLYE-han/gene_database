# seq_2M 数据格式抽查

检查时间：2026-10-15 17:08（Asia/Shanghai）。仅进行了只读元数据与少量数据检查，数据仍在传输；没有修改数据、建立索引或执行完整近邻评测。机器可读快照见 [seq_2M_inspection.json](seq_2M_inspection.json)。

## 1. 路径与格式

用户提供目录为 `gene_database/Data/seq_2M`，当前实际数据根目录为 `gene_database/Data/seq_2M/seq_2M`，存在一层同名嵌套。

| 相对实际根目录的路径 | 形状 / 类型 | 含义 |
| --- | --- | --- |
| `base/part_00.npy` | (2,000,000, 2560)，little-endian float32，C-order | 未归一化的数据向量 |
| `queries200K/queries.npy` | (200,000, 2560)，little-endian float32，C-order | 查询向量 |
| `queries200K/query_ids.npy` | (200,000,)，little-endian int64 | 查询在 base 中的全局行 ID |
| `queries200K/{cosine,euclidean}/knn/000000000_000200000.npz` | 各一份 top-100 标签 | 两种距离的独立 ground truth |

上述独立 NPY 文件头均占 128 B。base 预期总长度为 20,480,000,128 B；queries 预期 2,048,000,128 B；query_ids 预期 1,600,128 B。

每份 NPZ 是 ZIP_STORED（未压缩 ZIP），成员为：

- `query_start` / `query_end`：int64 标量，0 / 200000。
- `query_ids`：int64，(200000,)，与独立 query_ids.npy 的整个数组一致。
- `metric`：Unicode 标量，分别为 `cosine` / `euclidean`。
- `ids`：uint32，(200000,100)，该实验库中的邻居行 ID。
- `distances`：float64，(200000,100)，按距离非降序排列（已抽查前 64 行）。

指标契约：cosine 标签存 `1-cosine`；euclidean 标签存原始向量的欧氏距离，未平方、未归一化。若 DHDGS 使用归一化后的平方 L2，其返回距离与 cosine 标签满足 `d_l2_squared = 2*d_cosine`；原始平方 L2 与 euclidean 标签满足 `d_l2_squared = d_euclidean²`。ID 排名可直接比较，数值误差检查必须转换单位。

## 3. 数据来源与评测影响

sampling_config.json 记录：此 2M 数据由已有 seq_200M 的前 2M 行形成，源清单为前 20 个 HDF5 shard，各 100K 行，顺序为数值 shard ID 后接行顺序。因此该文件是顺序前缀子集，不应未经检验就称为百亿数据的随机代表样本。

查询从该 2M base 无放回采样，seed=20261013、生成器 numpy.PCG64，按全局 ID 升序存放。两种搜索配置均声明 `sampled_exact`、float64、k=100、`exclude_self=true`、TF32 关闭。实际 NPZ metric 字段用于区分两种距离，不只依赖可能沿用旧值的外层 manifest。

后续实现必须：

1. 分清“当前 2M 实验库”“此前规划的 200M 验证规模”和“长期百亿规模”，每个索引和结果记录数据身份。
2. 结果排除当前查询自身的全局 ID；该点仍可作为图导航入口/中间节点。不能只删除返回数组第一项，也不能排除所有相同值但不同 ID 的向量。
3. 明确这是库内留一检索评测。可以据此测 ANN 质量，但不能直接推广为新查询分布/生物学泛化效果。
4. 保留测试集隔离约定；200K 不自动拿来反复调参。若需拆分校准集，与用户明确约定并固定清单。
5. 仅对当前已到达前缀做小实验时，应重新计算该前缀库的 ground truth。不能简单过滤全 2M 的 top-100 后当成前缀库的精确 top-k。
6. 完成传输后核对文件长度、来源校验和定义及内容一致性，再执行全量样本检查与标签验证。当前不对写入中的 base 进行完整哈希或修改。

## 4. 百亿规模的新增约束

以下为 D=2560、十进制容量、RF=1、不含校正因子/ID/页对齐/缓存/临时空间的理论裸数据量：

| 数量 | float32 原向量 | RaBitQ 1 bit | RaBitQ 4 bit |
| --- | --- | --- | --- |
| 2M | 20.48 GB | 0.64 GB | 2.56 GB |
| 200M | 2.048 TB | 64 GB | 256 GB |
| 10B（100 亿） | 102.4 TB | 3.2 TB | 12.8 TB |

百亿若仍只用 4 台服务器，平均每台原向量 25.6 TB、1-bit 裸编码 0.8 TB、4-bit 裸编码 3.2 TB。每台约 1 TB RAM 的情况下，1-bit 编码也几乎没有给副本、元数据、缓存和并发状态留下余量；RF>1 时情况更紧张。当前 4 台硬件用于实验，长期节点数/内存/SSD 容量不能假定保持不变。

- 百亿全局 ID 超过 uint32 上限。协议、manifest、边界 ID、ground truth 工具使用 64 位全局 ID；当前 uint32 标签读取时拓宽。局部 ID 是否可用 uint32，需检查各库的保留位和实际容量上限。
- 构建、shuffle、边合并和编码必须流式/外存化；单个全量距离矩阵、全局全量图驻内存或每查询全库 visited 数组均不可作为默认实现。
- 路由采样需要显式内存预算。百亿的 0.1% 为 10M 样本，裸向量即 102.4 GB；1% 为 100M 样本、1.024 TB，尚未包含 HNSW 边。不能无限沿用固定样本比例而不检查路由容量。
- 远端编码缓存、边界邻接表、查询状态和在途请求都必须有字节/数量上限；容量不满足时需要报告不可行，并讨论增加节点或改变编码驻留策略。
- 2M 数据极易完全进入 RAM。它用于算法筛选与通信正确性；SSD 结果需显式受控内存/缓存实验，规模结论须经更大数据与真实多机复核。
