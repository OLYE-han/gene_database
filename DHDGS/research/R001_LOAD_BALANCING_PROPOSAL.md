# R001：查询工作集合驱动的部分子图复制与负载分流

版本：v0.1，2026-10-26（Asia/Shanghai）。状态：**供审阅，未实现、未实验验证**。关联：[Research R001](../Research.md#r001)，尝试R001-A03。

2026-10-26补充：[完整算法流程](R001_REPLICATION_ALGORITHM.md)，关联尝试R001-A04。细化失衡检测、热点选区、入口登记、子图物化、RDMA传输、预热、渐进接流与回收；以下总体设计的状态仍为待验证。

建议采用“慢速维护副本、快速分配查询”的方案：根据实际搜索工作集合选择热点区域，将原图的一部分复制到有余量的节点；顶层在原节点和可服务副本之间分配入口。先验证静态副本，再引入动态触发，保持每数据节点64个搜索线程。动态网络资源管理继续独立工作，不能代替搜索扩展函数发起查询分支。

## 1. 当前问题与可期待收益

[现有并发实验](../test/concurrency_best_20261023/REPORT.md)中，1024并发下三个数据节点的情况为：

| 节点 | 搜索CPU核当量 | 每分支平均计算排队 |
|---|---:|---:|
| Intel-31 | 57.54 | 51.76 ms |
| Intel-32 | 55.00 | 6.64 ms |
| Intel-30 | 37.83 | 2.53 ms |

这支持“可将一部分工作从Intel-31/32转移到Intel-30”的假设。但CPU核当量不等于硬件额定容量，不同机器/NUMA放置的有效服务能力需要分别测量。负载均衡应转移计算和I/O工作，不能只把入口请求数分成三等份。

作为量级示例：若三机服务能力相同、总工作量不变且搬运零开销，上述负载完全摊平约为50.12核当量；最大值/均值约1.15。这只是该工作点的理想均衡因子，不能承诺QPS提升15%，也不能外推其他负载。排队接近饱和时，p99可能比吞吐更敏感。只转移Intel-31的工作后，Intel-32可能成为下一个热点，控制器必须重新评估全部节点。

当前数据主要命中页缓存；接收至入队还有独立的长尾问题。前者影响复制预热与SSD结论，后者属于[R002](../Research.md#r002)，不能把所有等待归因于分片不均。

## 2. 设计边界与组件职责

```mermaid
flowchart LR
    Q[用户查询] --> H[Intel-35 HNSW入口]
    H --> P[按查询匹配和预计完成时间选入口]
    P --> A[A 原节点]
    P --> B[B 原图及已发布副本]
    A --> M[顶层按现有分支协议合并结果]
    B --> M
    A -. 低优先级复制原图区域 .-> B
    S[低频负载与访问统计] --> C[顶层副本控制器]
    C -. 发布目录与分流额度 .-> P
```

图中A/B是同一查询首跳的备选，不表示为了均衡同时启动两份相同查询。后续并行分支仍由原跨机扩展函数决定。

| 组件 | 新增职责 | 热路径约束 |
|---|---|---|
| 数据节点搜索线程 | 对少量查询记录展开集合、候选发现依赖、工作量和出口 | 线程内采样/聚合；不在每次展开争用全局统计锁 |
| 数据节点后台复制服务 | 打包、接收、校验和预热不可变副本 | 有界队列、限速，独立于搜索工作池；不能侵占全部SSD/内存带宽 |
| Intel-35副本控制器 | 低频选区、选目的地、发布和回收 | 控制计算不在每条查询的HNSW线程内执行 |
| 顶层分发线程 | 查询适用性判断、比较入口、消耗分流额度 | 使用本地只读快照；每查询不新增负载探测RPC |
| 数据节点本地定位 | 查找当前查询可见的副本记录和编码 | 原索引加不可变覆盖目录；不重写全局归属表 |

第一版只复制，保留原节点的图和向量；只改变顶层首跳的可选位置。普通跨机动作仍使用原有规则，不把所有新副本自动加入所有查询的远端候选位置。

## 3. 如何识别值得复制的向量

### 3.1 按搜索工作量与查询群体识别热点

入口命中次数和顶点访问次数都不充分：同一入口可能服务不同搜索区域，单个频繁访问的桥接点也可能无法独立承接查询。

对采样查询q记录以下内容：

- HNSW入口、路由候选及其距离特征；只使用在线可得特征判断以后查询是否适合某副本。
- 实际读取/展开顶点集合X(q)、发现候选的父子关系、未展开候选所需编码集合。
- 线程CPU时间、工作线程占用时间、估距/精排次数、逻辑与物理读量、跨机出口及后续工作。
- 查询实际完成状态、预算、分支路径。必要时离线关联最终召回；在线路由不能使用未知真值。

CPU工作与线程占用时间分开记录：等待SSD会占住当前固定查询线程，却不产生同等CPU消耗。排队时间不计入某个顶点的计算热度，否则拥塞会反过来制造假热点。

先用入口分组，再根据采样的展开集合重合程度拆分/合并查询群体g。可以使用MinHash/Jaccard筛选相似集合；首版无需在在线路径训练复杂模型。实际代价先按批次分摊，明确这种估计精度，不对每个距离计算插入计时调用。

同时区分首跳任务与远端子任务。首版只改首跳，因此不能把A收到的所有远端工作都算作可卸载机会；阶段A必须报告“可由入口改道影响的CPU工作比例”。若热点主要由其他节点的后续扩展造成，入口副本方案可能覆盖不足，需要另行设计由扩展函数选择副本位置的版本，不能让网络调度器绕过扩展函数分流。

```text
heat(v) = 窗口内归属于v的CPU工作 / 窗口时长
coverage(q,R) = q在区域R内的CPU工作 / q在来源节点的CPU工作
```

coverage只用于筛选。它既不是“查询能在副本完成的概率”，也不是召回保证；复制改变本地/远端关系后还必须实际运行查询。

### 3.2 区域的选择目标

候选区域按“真正减少热点节点多少工作”排序，不能按“改道多少查询”排序。回源和重复工作必须扣除。

```text
delta_w_j(R,B) = 使用B副本后节点j每条匹配查询的CPU工作
                - 原始执行时节点j每条匹配查询的CPU工作

load'_j = [work_rate_j + p * lambda_g * delta_w_j(R,B)] / capacity_j
```

lambda_g为该查询群体到达率，p为分流比例，work_rate和capacity的单位都是CPU秒/秒。来源A必须满足delta_w_A<0；目标B的代价包含重复工作和其原生业务受影响的部分。I/O带宽、IOPS、工作线程占用和内存带宽另设约束，不能仅用CPU模型描述冷SSD搜索。

在副本RAM/SSD预算、目标余量和质量约束下，选择能降低最大归一化负载的区域与p。历史轨迹只能给delta_w的初始估计，静态副本实测后才能校准。多个区域覆盖同一查询时只选一个首跳方案，收益不得重复相加。

## 4. 如何切出子图

### 4.1 使用核心、必要邻域、区域外出口

R包含一组可以实际服务目标查询的向量记录，而非几个孤立热门点：

1. 以目标查询群体高工作量的连续搜索片段和入口为核心。
2. 依照真实候选发现关系补充连接路径及经常被展开的邻域。
3. 保留原邻接表中的全部外部出口；不因邻居未复制就删边。
4. 在额外字节预算、净卸载收益不足或覆盖收益趋缓时停止生长。

不要求严格封闭：递归复制所有邻居容易膨胀成整片。也不重建一个独立小图；首版保留原始图结构，避免同时改变拓扑和位置而无法归因。

采样查询可表示为连接一组共同访问顶点的超边；这比只最小化普通图的跨分片边数更贴近beam search。首版用多种子、成组生长的启发式：比较加入一组依赖顶点后增加的预计卸载量/额外字节。由于点之间有依赖和组合收益，不声称贪心具备近似保证。

### 4.2 复制内容与容量核算

```text
副本 = R的原向量和邻接记录
     + R及其出邻居估距所需的RaBitQ编码/校正元数据
     + 编码中心、旋转及版本依赖
     + global_id到记录位置的索引、入口集合和校验信息
```

只为R保存完整记录；某个外部邻居如果只需估距，先保存相应编码和位置，不递归复制其完整记录。当前2560维记录约12 KiB，实际预算还必须计编码、目录、文件头和临时构建空间。

按目的节点当前已有内容去重，计算**新增**RAM和SSD字节；不同副本复用的数据按版本引用计数。编码保持原中心/旋转和精排距离契约，不在B重新量化为另一套不可直接比较的距离。

物理实现建议为原只读索引加独立副本文件及只读覆盖目录。发布与回收时原子替换目录快照；查询固定快照，不在搜索时修改共享归属数组。顶层只保存路由入口到副本描述符及适用性摘要，不保存全量复制向量的位置表。

## 5. 如何把查询分配给副本

### 5.1 先判断副本是否适用

HNSW仍正常找到入口。入口ID命中副本目录只是第一步，还要使用入口距离、备用入口距离差及离线校准的查询群体标签判断适用性。信息不足、目录过期或回源风险过大时使用原入口。

第一版可用小型查表模型：入口组＋距离区间→区域、本地覆盖/回源风险及预计服务时间。模型须在独立查询上校准，不能拿同一批训练轨迹同时证明泛化收益。

### 5.2 比较预计完成时间并限制分流量

```text
T_hat(q,j) = 接收入队时间估计
           + (已有未完成工作 + 新派发预留工作) / 有效并行服务能力
           + q在j的服务时间估计
           + 首跳传输时间
           + 出区概率 * 出区造成的额外完成时间
```

工作积压项采用预计剩余的工作线程占用秒数，容量使用同单位校准；不是把CPU秒直接当墙钟秒。该式是可校准的启发式，分支并行和排队相关性使其不能作为精确时延公式。出区惩罚须使用额外关键路径代价，不能把各分支的全部时间简单相加。

当B预计比A快且B仍有余量时，逐步提高分流比例。即使B当前队列为空，也不能瞬间接收所有热点流量。粗略的CPU约束为：

```text
p <= B可用CPU秒/秒 / (lambda_g * B每条分流查询新增CPU秒)
```

同时取I/O、占用线程、网络和空间约束中的最小允许比例。使用query_id的稳定哈希在A/B间分配，不使用向量内容哈希，避免同一热门向量的重复查询永远集中到一台机器。实际副本缺失或版本不可用时不能假装执行成功。

负载摘要拟每100 ms传播一次；顶层跟踪摘要之后尚未反映的派发工作，避免陈旧负载造成集体涌入。摘要需携带接纳进度，预留额度与已上报工作对账，不能永久重复计算。给分发线程分配小批额度以避免新增全局热点锁，未用额度定期归还。

## 6. 最需要审阅的语义限制

当前实现按物理节点记录visited_nodes，一个查询最多在同一物理节点启动一次。部分副本与这个约束存在真实冲突：

```text
在B搜索A的副本 → 到A搜索副本以外区域
             → 后来发现B原分片的重要候选
```

最后一步会因为B已经访问过而受限。B初次搜索时允许访问“B原图＋该查询选中的副本”能处理当时已发现的本地候选，但不能保证提前发现所有后来才出现的候选。增加副本不自动保证召回不变。

建议分两种明确模式讨论：

| 模式 | 语义 | 收益与代价 |
|---|---|---|
| **v0.1推荐起步：物理节点一次访问** | 保留既有去重和预算协议；副本仅作为入口选择，优先筛选低出区、低回访风险查询群体 | 改动范围小，便于验证小副本是否值得；对高出区工作负载可能根本无收益，必须保留这一负结果 |
| 后续可选：逻辑任务去重 | 按查询＋逻辑区域/任务＋版本去重，同一物理节点可承接不同逻辑工作；全局预算仍统一 | 能更完整地支持部分复制，但改变此前的物理节点一次访问要求；需要重新设计任务终止、候选合并和重复工作控制 |

本提案不擅自实施第二种模式。第一种模式在B查本地覆盖目录后使用原始owner回源；所有远端搜索仍须经现有扩展函数批准。仅需做原图记录读取的后台复制不会启动任何查询分支。

质量按独立测试集验证：Recall@10≥0.95，并检查相对原配置的非劣性；可先讨论将允许差值设为0.2个百分点。低于下限时先减少适用查询范围或扩大副本，不偷偷提高预算。若同预算始终无法满足，记录该模式的限制并讨论是否改变访问语义。

增加以下诊断：副本适用性误判率、出区/回源比例、回源CPU工作、已访问节点规则导致的候选跳过数、总重复估距/展开。候选跳过数不能直接换算召回损失；小规模诊断回放可放宽访问限制作参照，但须标为不同语义，不混入正式性能结果。

## 7. 何时复制、何时回收

### 7.1 两个时间尺度

- 快层：每条查询只使用已发布副本；约100–500 ms调整分流额度，限制单次变化幅度。
- 慢层：约1 s评估一次持续拥塞、热点可复制性和资源余量；满足多窗口条件后才创建副本。

建议同时满足四个条件才启动：A确有计算/I/O服务拥塞；B有对应资源余量；存在可净卸载的热点区域；热点预计持续时间足以覆盖复制、预热和回本。若等待主要在接收控制而计算空闲，应优先定位R002，不能直接用CPU负载均衡解释。

热点寿命预测本身不可靠时，使用保守持续时间门槛和小容量探测，统计错判代价；不能假设预先知道未来查询分布。来源侧回本时间可粗估为：

```text
来源侧CPU回本时间 = 来源为创建副本额外消耗的CPU秒
                  / 副本生效后来源每秒净减少的CPU秒
```

这只是来源的必要检查，不能代表集群净收益。复制期间业务退化、目标CPU/SSD代价、预热成本及热点消失后的浪费都需单独核算；最终比较整个生命周期内SLO达标的完成查询数。

### 7.2 发布、降温与回收

```text
候选 → 复制中 → 校验完成 → 预热 → 可路由
     → 降低/停止新分流 → 在途查询排空 → 回收
```

复制由A直接发到B，顶层只传元数据。B验证ID、原图版本、编码依赖、记录数和校验和后才允许顶层发布；先以小比例接流，再提高额度。副本目录携带region_id、graph_epoch、replica_version、入口集合和可用位置，查询报告带上所用版本及来源逻辑区域。

原分支树、预算、心跳和报告合并继续使用现有协议；计算线程仍在本地候选耗尽/预算耗尽后释放。拒绝尚未接纳的过期副本请求可转回原入口；已接纳后状态不明的任务不能直接在别处重跑，必须遵守现有幂等/失败协议。热副本不意味着已具备崩溃恢复或在线更新一致性。

通过高低阈值、冷却期、最短保留期和渐进分流避免振荡。停止新分流后保留文件直到版本引用和在途任务都排空；队列变短不能成为立刻删除副本的理由。


空间比例的分母固定为本轮开始时已有图/编码/目录的实占字节，包含原几何重叠副本，但不随新增副本递增。RAM、SSD和临时空间分别做硬预算检查；编码依赖可能使某候选先触达RAM限制。利用率阈值按各节点实测服务容量归一化，不直接用线程数代替CPU容量。正式实现还需校验目标字段、统计量口径与不支持的模式，不接受拼错参数静默失效。

第一轮先观察，不把这些阈值称为最优。后续至少扫描副本预算1%/5%/10%、采样开销和分流比例；触发时间须根据复制耗时和热点持续性再定。max_load_age过期时逐步收回副本额度，避免用失效信息放大拥塞。

## 9. 分阶段验证，不同时引入全部变量

| 阶段 | 要回答的问题 | 必须产物/停止条件 |
|---|---|---|
| A：机会分析 | 小副本是否能承接显著工作？热点是否持续？ | 容量—工作覆盖—出区风险曲线；独立验证集；采样开销。若工作集合太散，先否定小副本路线 |
| B：静态副本 | 固定区域真实减少了A的工作吗？ | 基线与副本在同预算、同线程、同负载下对照；实际源工作减少、目标新增、重复工作、召回和p99 |
| C：路由策略 | 负载与查询适用性信息各有多少价值？ | 静态分流、只看负载、只看查询匹配、二者加回源代价的消融 |
| D：动态复制 | 收益能覆盖建副本和流量变化成本吗？ | 稳定热点、短突发、热点迁移、周期变化及均匀负载；完整时间曲线和复制期间退化 |

B阶段的基线至少包含：无复制；随机同大小复制；访问频率选点；固定小分片/几何区域；查询工作集合子图。容量允许时加入整分片副本，作为更简单方案的成本/效果参照；不能把它的更高空间代价隐藏掉。

seq_2M在当前机器内存条件下很小，整片复制可能已经足够好。必须给出相同额外空间下的对照及空间—吞吐—p99曲线，不能只通过不允许简单基线使用内存来制造创新收益。

固定：数据版本、距离与RaBitQ、64搜索线程、全局搜索预算200、网络配置、CPU/NUMA放置、客户端和测量边界。每个方案均记录实际搜索工作量；不靠新增线程或增加搜索预算制造复制收益。

工作负载分为真实分布、可控稳定偏斜和热点迁移；训练/选择区域与评估查询分离，不把重复2000条查询的200万请求当成200万个独立样本。稳定段拟持续数分钟，并覆盖多个复制与冷却周期；冷热SSD实验独立进行，保持统一缓存/内存预算。

同时做固定到达率开环测试和128/256/512/1024/2048闭环并发对照。开环用于比较同负载p99和排队稳定性；闭环用于观察吞吐曲线。按预先声明的延迟SLO统计有效QPS，避免通过排更长队列提高表面吞吐。

### 验收与研究结论

- 正确性：无重复启动物理节点、预算超支、版本错配、缺失最终报告；取消、重试和回收不悬挂。
- 质量：独立查询Recall@10≥0.95；配对比较相对基线的退化，并报告按独立查询计算的置信区间。0.2个百分点非劣界是待审阅建议。
- 净卸载：A实际CPU/占用线程工作下降；B能承接且原生请求不产生不可接受的尾部退化；出区、回源和重复工作均计入。
- 性能：以同到达率p99为主要指标，以同质量、同延迟SLO的有效QPS为第二指标；可将至少10%可重复改善作为第一阶段目标，正式实验前固定主指标与阈值，不能事后挑选通过项。
- 资源：记录副本和预热开销、额外RAM/SSD、源/目标读写量、NUMA位置、复制期间损失和收敛时间。低频观测开销建议目标低于2%，仍须实测。
- 网络：延续平均和预先固定近p99样本的保守网络/控制占比低于30%的既有口径，同时报告绝对毫秒；搜索等待减少可能使网络占比升高，这不代表网络本身变慢，但仍不能声称原占比目标已满足。
- 负结果：均匀流量不得为了“展示均衡”强行复制；短热点来不及回本、整片副本更好、物理一次访问阻碍召回等都作为研究结论保留。

重点图表：三个节点队列/CPU随时间变化，标记复制开始、发布和分流比例；副本容量—净卸载—回源曲线；QPS/p99与偏斜程度曲线；动态全过程有效吞吐；典型跨节点近p99查询时序。不要只展示副本完全预热后的最好窗口。

## 10. 审阅重点与潜在论文主线

建议先认可阶段A/B的验证路径，再确定动态控制细节。三个需要共同确定的取舍是：

1. 是否坚持物理节点一次访问作为本轮硬约束；若副本回源使收益或召回受限，是否另行研究逻辑任务去重。
2. 愿意为负载均衡增加多少RAM/SSD，建议先画1%/5%/10%的成本曲线，而不是先选一个永久固定比例。
3. 首轮更看重同负载p99，还是指定p99上限下的最大QPS；建议沿用p99优先，并同时给吞吐曲线。

可能的论文主线是：**在副本容量和搜索质量约束下，根据ANN搜索依赖构造部分副本，联合决定复制位置、热点生效时机与入口分流，获得实际计算卸载。** 需要证明查询工作集合方法比热点顶点、固定小片或整片复制有更好的成本—性能关系。

复制、按负载路由和快慢控制本身不是新颖性结论。相关工作与证据边界见[Research文献表](../Research.md#literature)。通过实验的具体机制才迁入DESIGN并关闭相应问题；本审阅稿不改变R001“研究中”的状态，也不生成新的性能实验日志。
