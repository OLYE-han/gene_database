# R001-A07：顶点热度、多种子扩展与半径约束评审

2026-10-26，设计讨论；关联R001/R005/R010。用户提出逐顶点计数及上次访问时间、热度top-K种子、几何聚合/拆分、多种子扩展与 `radius = alpha × shard_radius`，alpha初值0.2。本页为可行性分析和待验证改进，不是已实现或已验收的能力；未启动新实验，未写入DESIGN已验证机制。

## 1. 适用价值

顶点热度可覆盖非HNSW入口附近、搜索中途和跨机进入后形成的热点，补充目前只按原始入口组选择工作集合的限制。多种子可避免单入口局部观察遗漏共同工作；按几何结构拆分有助于避免把不相邻热点复制成一个大区域。局部统计也可减少向顶层传输完整轨迹，但该收益取决于采样和合并实现，须测量。

热度高表示顶点经常被处理，不直接表示包含它的小副本能卸载完整查询。导航枢纽可能服务多个方向，复制少量枢纽后仍立刻回源。选区应保留少量查询/部分状态轨迹，验证净卸载和出区风险。

## 2. 时间语义需要修正

用户给出的更新是：访问间隔不超过W则累加，超过W则重置1。这统计的是“相邻访问间隔始终不超过W的一段活跃期”内的总次数，不是最近W的滑动窗口计数。例如W=1s，每0.9s访问一次，长期累积不会重置，最近1s其实只有1～2次。旧热点一旦不再访问，也不会触发重置，堆中的历史高值可能长期残留。

可对照两种方案：

- **时间桶近似滑窗**：把W划分为B个桶，按epoch轮转。计数取覆盖最近W的桶之和，边界误差由桶宽决定；不称为精确逐事件滑窗。每顶点保存全部桶的内存较大，可在有界活跃候选表中保存、按线程统计后合并。
- **指数衰减热度**：更新 `h <- h * exp(-(t-last)/tau) + event_weight`。比较时仍需衰减到同一快照时间；不能直接比较最后一次写入的h。tau是时间常数，半衰期为tau×ln2，不是固定窗口W。所有顶点同tau时，时间推进不改变两个未更新条目的相对顺序，可优化维护，但数值稳定及到期淘汰仍需处理。

先比较时间桶与指数衰减，不默认两个含义相同。持续性和突发性可用短/长两个时间尺度分别观察，避免复制启动后热点已经消失。

## 3. 定义访问并控制统计开销

主计数建议从“该query在该物理节点成功领取并展开此顶点”开始，与现有本机查询展开去重对齐。同一向量作为邻居被看见、做RaBitQ估距、真正读取并展开、进入最终top-k，是不同事件，不能混计。成功展开频率可结合分组/批次平均服务成本形成CPU或I/O热度；排队时间不记为顶点工作量。

当前64～96个工作线程可能同时更新同一个热点。C++普通非原子读写会产生数据竞争；两个独立原子字段也不能自动保证“读上次时间→决定重置或累加→写新时间”这组操作一致。热顶点共享原子和每次访问更新全局top-K堆还可能形成缓存行争用，不能因没有互斥锁就认定无开销。

全量每顶点两个64位字段原始成本为16B：2M约32MB，200M约3.2GB，10B约160GB（十进制，不含复制/对齐/索引/堆/桶）；三机分摊仍约53.3GB/机。大数据量还需避免扫描全部计数器寻找top-K。

候选实现：工作线程使用有限容量局部频繁项表或局部聚合缓冲，按周期交给后台合并，后台维护有界候选和top-K。局部top-K的并集不一定包含全局top-K，不能声称精确；需要保留更大的候选集、可合并摘要和误差证据，再对候选精计数或抽样核对。采用每线程完整计数数组会将内存乘以线程数，也不可默认使用。

若坚持精确计数，需单写者分区/消息聚合或正确的原子更新协议，单独测开销；访问时间使用节点本地单调时钟。不要求每次访问一次系统取时，可评估批次时间戳带来的误差。

## 4. 多种子聚合与扩展的风险

K个2560维种子全对全距离为O(K²D)，10000个种子有约5000万对，不能把触发后的这个成本当作免费。可用有界种子数、增量几何聚合、代表点分配或近似候选距离筛选，必要时最后精确检查；这些都是待消融的替代实现。几何中心可以热度加权，但中心本身通常不是图顶点，实际种子仍需选择真实顶点。

高热度种子可能位于多个簇，或集中在同一个导航枢纽。加入种子多样性可降低重复覆盖，但几何距离大/小不完全等于查询工作独立/共享。应同时观察同查询共同展开和发现关系。

“从多个种子扩展直到相遇”可用来寻找连接路径，但它只提供一种连接证据：有向图里相遇甚至不代表互相可达；不同方向的搜索可能仍依赖区域外顶点。只复制连接热点的细走廊，可能一两步就出区。现有beam/best-first搜索也不是随机游走，静态图出边比例只能作为先验。

建议保留完整原邻接、有限halo与量化依赖，扩展候选优先按预计来源CPU卸载/新增实际字节排序，用采样真实搜索流量校正。边际收益可能依赖成组加入路径，不能宣称单点贪心有最优保证。发生跨源分片依赖时，应按现有预算保留出口或显式扩展维护协议，不在后台切图中隐式创建查询分支。

子图构建使用有资源上限的后台工作池：限制并行构建数、CPU、读取/复制速率和取消条件。新建线程并不创造空闲CPU；来源本来繁忙时，构建竞争可能抵消分流收益。热点失效或目标失去余量时应停止/拒绝发布。

## 5. alpha=0.2的含义和限制

应先定义几何半径：中心可用均值或代表点，半径可用最大欧氏距离或距离分位数；不能与图跳数半径混用。建议基线把来源半径定义为到来源中心欧氏距离的Q95（用有界均匀样本估计，记录误差），而不是对异常点敏感的最大值。Q95不包含所有点，必须明确处理尾部点和路径依赖。

在未归一化ESM向量上沿用现有L2语义，不为选区暗改归一化。若实现中使用平方L2，`r=alpha*R`对应 `r²=alpha²*R²`：alpha0.2对应平方距离阈值0.04倍，而不是0.2倍。

把 `r0=0.2*R_source` 作为候选初始尺度值得测试，但不足以同时约束副本质量和大小：

- 来源可能多模态或被异常点拉大，全局R不是热点局部尺度。
- 密度不同，相同半径对应的记录数可能相差很大；每条记录边数/依赖不同，字节数还会继续变化。
- 高维下距离可能集中，半径缩放与包含点数可能高度非线性；理想均匀d维体积按alpha^d缩放，但不能把ESM的2560维直接当作实际内在维数。
- 强迫每个区域半径相同，可能使稀疏区域欠覆盖、稠密区域超容量。核心半径小不意味着需要复制冷点把球填满。
- 热点种子半径小不代表相关查询的工作集合也小，搜索路径可能先出区再返回。

较稳妥的候选控制是“alpha提供初始尺度，局部密度与真实工作校正，字节为硬约束”：对各热点组估计第m个来源邻居的距离作局部尺度（m与top-K种子数、query top-k分开命名）；按半径递增的候选包测覆盖/出区/净卸载，达到质量门槛后选择最小成本包，而非强制所有包到同一半径。若任何允许大小都无法同时满足质量与容量，则拒绝该热点或拆成多个有独立入口的区域。

## 6. 建议的完整候选流程

1. 节点后台从有界统计中形成同一时间快照下的热点候选；不把未过期的历史累计值当成当前热度。记录采样误差和维护开销。
2. 持续失衡触发后，冻结本轮候选快照；按热度×估计服务成本及空间/查询多样性挑选多种子，避免构建过程中追逐不断改变的排名。
3. 几何上聚合/拆分多模态热点，保留原始HNSW入口或可验证的peer入口映射。热点顶点不一定是HNSW样本，缺少入口映射的副本可能没有请求进入。
4. 以alpha提供初始尺度，按局部密度、实际共访问/发现关系扩展有限路径及halo；记录每次加入的向量、依赖码及字节。种子相遇是中间里程碑，不能单独作为完成门槛。
5. 检查总字节、量化依赖、目标剩余SSD和构建干扰；用固定预算查询及peer部分状态校准条件召回、首次出区、副本内实际展开、回源工作和来源净CPU节省。目标增加的CPU工作是承接负载，不能全部作为“浪费”扣除；应检查目标余量及全系统额外工作。
6. 通过后复制、预热和渐进接流；失败则拒绝或尝试受限扩展/拆分。不同区域可以有不同半径。扩大可管理区域数量前，需扩展当前仅一个活动区域的控制器与目录冲突/回收机制。

## 7. 待执行的对照与指标

保持完整200K不同查询、同顺序、预算200、同搜索线程/网络配置，控制器不读取评测真值。先在已记录的完整轨迹上做候选分析，再做实时统计开销和在线发布实验。使用不同时间段做选区与质量验证，根入口与peer部分状态分别评价。沿用真实自然流，不以构造偏斜子集替代验收。

建议分阶段，避免一次修改后无法归因：

| 阶段 | 对照 | 主要判断 |
|---|---|---|
| 统计 | 无新增统计、用户原计数、时间桶、衰减计数；原计数标明活跃期语义 | 每展开CPU/缓存争用、RAM、采样误差、冷热点残留、热点识别反应 |
| 选区 | 当前入口工作集合、顶点热度同大小、几何多种子、热度+真实依赖扩展 | 固定额外字节下覆盖/来源卸载、构建时间、首次出区/回源 |
| 半径 | alpha=0.05/0.1/0.2/0.4；分位数定义固定；局部密度尺度对照 | 实际记录/字节与alpha关系、质量—容量曲线，不要求半径相同 |
| 发布 | 同固定质量和字节预算、交错重复 | QPS/p99、复制期间前台退化、来源CPU净下降、目标成本、条件召回 |

半径扫描是待实验建议，不表示0.05或0.4安全；先用轨迹和容量检查排除不可行值。热点时间常数/桶数、候选数和种子数独立调参，先测热度持续性，不随意捏造最佳W。

持续保留每区域切图/复制/发布/失败次数、入口选择/完成、peer选择/完成、覆盖的不同查询数及复制/预热字节。新增统计维护开销、检测→可服务时间、热点剩余寿命、首次跨出前副本内展开数和剩余预算分布。全量Recall接近不足以掩盖命中子集下降，必须做条件质量对照。

可能的研究贡献是：在有界维护资源和容量下，用时间热度与搜索依赖共同控制区域生长和入口适用性，预测可卸载工作并减少回源。仅使用计数器、top-K、聚类和半径阈值不足以据此断言创新性，仍需相关工作及公平实验对照。
