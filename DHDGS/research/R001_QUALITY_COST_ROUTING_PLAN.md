# R001：固定副本诊断、质量与成本准入、目标总容量调度

2026-11-04；设计提案，待讨论、未实现、未执行新实验。关联 F02/F05/F07/F10/F23、R001/R004/R008；[研究台账](../Research.md)。本提案不作为 DESIGN 中已验证能力。

后续状态：下文早期提案中的32次/条件平均50%已被用户后续指令替换；当前规则为至少20次回源且“每入口完成请求的期望回源剩余预算”超过阈值。最新八档结果及下一步执行顺序见文末“八档收敛后的快速验证计划”；历史提案不覆盖最新配置，也不代表已实施其中的质量/成本控制器。

## 依据与目标

[全部覆盖入口长测](../test/covered_entry_long_20261104/REPORT.md)中，原热点 node0 ready 均值109.30→33.60ms，但QPS仅20282→20655（+1.84%），搜索CPU/查询6.060→6.635ms（+9.48%）、整体Recall下降1.1805个百分点、p99变长。副本命中21.90%，其中78.30%计算回源。负载分配改善已经有证据，等质量吞吐收益尚未通过。

目标：在召回约束内减少瓶颈节点工作，并控制目标额外工作、控制/通信开销与尾延迟。CPU总成本允许小幅增加以换取瓶颈卸载，但需显式设置限额；不把三个节点CPU百分比相等作为优化目标。

正在开展的去除副本源驻留门槛实验属于独立变量；本方案实验开始前选择其已完成验证的版本并冻结源码。既有边界扩展函数继续决定回源/跨机搜索，路由控制器不通过I/O调度提前扩展远端，不恢复人为强制驻留。

## 一、固定副本和同查询配对诊断

### 固定什么

- 冻结子图成员、原边、量化依赖、入口全集、版本、物理放置、索引和包哈希；优先复用已保存包，若已清理则重建后冻结新哈希，不能声称与旧图完全相同。
- 固定搜索语义、D200、beam、每节点64搜索线程、RDMA模式、CPU亲和、客户端、缓存及背景负载观测。
- 测量前加载并预热；停止构建、升级、退役和自动份额变化，固定入口资格快照。正常心跳、失败恢复和查询状态回收继续运行。
- 每次请求仍有独立实例ID；原query ID仅用于配对和统计，不用于跨请求去重。不同方案的确定性路由使用相同的(query ID, occurrence, seed)。

### 最小对照

|组|固定副本|接流|回答的问题|
|A0|未加载|无|无副本基线|
|A1|已加载并同等预热|全部走源|副本内存占用、缓存与常驻服务本身的成本|
|B1|只保留一份或指定集合|固定25%份额|少量分流是否有源卸载与质量损失|
|B2|同B1|固定50%份额|目标成本与排队是否随接流增加|
|B3|全部冻结图|固定、归一化且互斥的份额|多副本之间是否相互竞争|

25%/50%为候选实验点，不是已推荐默认值；先筛选一份图，只有获得可解释结果才扩大矩阵。A0与A1隔离副本常驻成本，A1与B隔离实际检索成本。使用A-B-B-A交错及至少3个独立重复，保留所有失败和慢轮，控制每轮边界与统一预热。

分两种负载：

1. 固定到达率，初始选两方案稳态吞吐较低者的约70%–80%，用同一到达序列比较每查询源CPU、目标CPU、排队、质量和延迟；发送延误与拒绝都记录。
2. 固定C1536闭环，测成功QPS与p99；客户端结果消费、输出口径相同。通过短对照后再做30分钟稳态确认，不能拿低负载结果声称饱和吞吐提高。

负载仍使用200K自然查询；按query ID固定划分校准与验收身份，建议40K/160K，同一向量的重复回放不能跨集合。全200K性能另报，质量准入的最终证据来自未参与筛选的160K；如需要全200K独立验收，则另备校准查询，不从测试真值选图。

### 配对定义

对原入口e、来源s和副本r，同一query分别从源和副本开始，均执行完整的实际搜索路径：

```text
source_saved(q,r) = source_CPU_base(q) - source_CPU_replica(q,r)
extra_total(q,r) = total_CPU_replica(q,r) - total_CPU_base(q)
recall_loss(q,r) = Recall_base(q) - Recall_replica(q,r)
```

CPU使用各数据节点成功分支的累计搜索线程CPU，另计顶层/网络控制与构图进程CPU；不能把累计CPU当作端到端墙钟，也不能把并行分支时间直接相加为关键路径。失败单列、召回另给失败按零口径；CPU只比较双方完成的配对并报告覆盖率。

全量保留窗口计数、展开数、分支数、候选估距数、源/目标CPU和队列；少量样本拆分查询准备、候选/去重、RaBitQ、精确距离、pread、派发与报告，注明嵌套计时避免重复计费。按query ID聚合配对差值，bootstrap按唯一query ID抽样，跨运行的资源波动另报，重复回放不是新的独立样本。

必须分别回答：同样D200为何更多CPU；哪些分支是有效替代、哪些是额外成本；Recall损失来自哪些查询；多目标接流是否仅转移排队。不能仅从未命中/命中两个不同群体的均值推断副本因果收益。

## 二、入口的质量与成本准入

### 单位与语义

以 `(source, HNSW_entry, replica_version)` 为准入单位；所有被覆盖入口仍登记到目录，区分“结构可用”和“可接多少流量”。同一入口在多个副本上分别估计，不能按最早发布版本永久优先。

这是在当前全覆盖开放基础上新增的概率约束，属于待审阅策略变化。当前每5秒、至少32次直接回源、平均剩余预算>50%的关闭规则保留原语义，作为辅助保护；已有按该规则关闭的版本不被新控制器自动重新开启。

三种状态：

|状态|条件|动作|
|探索|结构可用但独立证据不足，或成本已过期|仅给全局预算内的小额探索流量，其余走源|
|合格|配对质量通过、源节省可信且目标可承受新增工作|进入统一份额调度|
|暂停|明确质量退化、无源节省、资源超载或版本失效|新请求回源；已开始查询自然结束|

样本不足表示未知，不能等同劣质，也不能因少量top-k集合不同而关闭整个家族。仅统计回源的32次阈值不承担质量置信度检验。

### 质量约束

使用精确真值计算Recall@10；top-k重合率只用于漂移告警，不能替代Recall。以query ID配对估计损失的上置信界：

```text
UCB95(mean recall_loss) <= 0.005
```

0.005为0.5个百分点，不是0.5%的相对变化。整体、实际分流群体及新增入口群体均报告；绝对Recall另设约95%的目标。证据不足时维持探索，不能以均值暂时落线内认定通过。

热门入口单独估计；长尾入口可共享结构/区域先验用于探索排序，但组内通过不能证明每个入口通过。候选策略选择后使用独立验收集复核，降低多候选挑选造成的乐观偏差。已有数据重复使用的阶段明确标为开发验证。

真实在线无精确真值时，质量只能继承近期独立校准并监控漂移；必要时降低份额、后台重新校准，不声称即时严格召回保证。严格质量模式下未知入口走源；研究探索模式下可低份额试探，并将探针和试探真实成本全部记录。

### 成本约束

每个动作估计完整物理节点成本向量 `c[e,r,i]`：一条从r进入的查询最终在节点i消耗的CPU-ms，包含回源与其他分支。保守估计源节省下界和新增成本上界：

```text
saved_LCB[e,r] > 0
added_UCB[e,r] = upper_bound(sum_i(c[e,r,i] - c[e,source,i]))
```

不简单要求每条查询的总CPU都减少：例如源省4ms、空闲目标增4.5ms可能提高吞吐。是否允许这0.5ms增量由全局成本限额和第三部分的瓶颈容量模型决定；源省0.2ms、目标增3ms的动作通常应被低排序或暂停。

准入不把“回源率低”当作必要条件：高回源但剩余有效工作少且质量好，仍可能有价值；低回源但漏掉近邻不算成功。线上默认仅处理正常完成结果中的标量，执行lane局部统计、后台汇总，不增加搜索热路径的全局互斥锁或同步影子查询。

### 探索成本

推荐将正常流量中的探索比例限制在全局0.2%以内，后台对照探针另设10 QPS和0.5%CPU开销的双上限；这些是待测起点，不构成Recall保证。主吞吐验收先关闭探针，用独立阶段校准；验证在线自适应时再计入探针真实CPU、网络与吞吐代价。

新版本成本独立统计，旧版本质量只作先验；定期按唯一query ID更新，防止一个热门向量重复百万次制造虚假的置信度。入口计数、估计摘要和候选列表有内存上限，完整向量不进入顶层控制表。

## 三、按物理目标总容量统一分配流量

### 避免独立家族反复争抢

当前家族内部份额上限不约束不同家族合计对同一目标的压力。新控制器统一计算所有入口、所有候选副本的概率，更新一次不可变快照；旧家族控制器退出份额写入，只保留生命周期建议，避免两个控制器同时改同一份额。

令e为原来源与HNSW入口，r包含原源路径和候选副本；`lambda[e]`为分流前入口到达率，`p[e,r]`为选择概率：

```text
p[e,r] >= 0
sum_r p[e,r] = 1
```

同一请求使用一次哈希抽样落到一个不重叠区间，只启动一个根任务；跨家族也遵守总和为1，不能每家族各投一次概率。源路径占剩余份额，候选失效回源。后续跨机扩展仍由搜索函数决定。

### 预测完整负载

```text
L[i] = B[i] + sum_e lambda[e] * sum_r p[e,r] * c[e,r,i] / 1000
```

`L[i]`为预测搜索CPU核当量；`B[i]`为未进入该优化集合的正常搜索工作，不能重复计入已建模流量；`c`为完整查询路径CPU-ms，因此副本回源的负载也落到来源节点。`C[i]`为当前有效搜索供给，依据稳定窗口、亲和性和背景竞争估计，不直接拿64线程当64个始终可用物理核。

主目标最小化最高归一化负载z：

```text
minimize z, subject to L[i] <= z * C[i] for every node i
```

同时约束质量合格动作、家族/入口概率、探针额度和总搜索CPU增量：

```text
sum_e lambda[e] * sum_r p[e,r] * sum_i c[e,r,i]
    <= (1 + epsilon) * sum_e lambda[e] * sum_i c[e,source,i]
```

epsilon初步比较0/3%/5%，用固定副本实验选择，而不是直接容忍本轮9.48%增加。若所有方案都超容量，维持正常排队/既有接纳背压并报告超载，控制器不通过更多复制或丢弃查询伪造吞吐提升。

CPU模型不能单独描述内存带宽、网络、SSD及串行依赖；用runnable等待、实际处理速率、网络排队、分支数/秒作反馈及资源守卫。仅在有待执行任务且供给充分时更新服务能力，节点空闲时观测到的低CPU不是其最大能力。

### 在线求解与稳定性

1. 每秒采集增量负载与队列，EWMA平滑；每5秒统一计算一次份额，质量/成本估计使用更长窗口。
2. 离线用约束优化求参考解；在线先用有时限的贪心小步调整：只接受降低最大预测压力、满足所有约束的流量移动，逐步重算源与目标预算，平局优先总成本更低者。
3. 每周期概率增量初值≤0.05，连续3个健康窗口才上调；目标超限时优先减少收益低/新增成本高的份额。网络或节点异常可立即回源，不等待上调冷却。
4. 加入份额变化惩罚及5–10秒保持期；稳定时少改动，不能以调整次数多作为自适应能力强的证据。
5. 每份目标额度在同一轮决策中只分配一次；跨入口/跨家族统一计费，预测CPU外另限制新增分支到达率，防止许多小任务淹没接纳/报告队列。
6. 后台发布带epoch、TTL的只读路由快照；查询线程只查表与哈希，候选数初值≤3（含源），截断候选的覆盖影响另测。不逐query扫描全部副本、加控制RPC或在线解优化问题。
7. 收到过期遥测时冻结上调；严重超载时按可验证的成本顺序下调，且检查回源后的源负载。无法找到健康路径时走既有超载处理，不能假设回源始终免费。

例如目标节点还可承接10个CPU核当量，副本A每查询增加4ms、B增加2ms，则共同满足 `4*rate_A + 2*rate_B <= 10000 CPU-ms/s`；不能让A、B各自都按全部10核计算可接流量。若二者还会回源，来源节点也必须同时满足其负载约束。

## 四、参数、验收与实施顺序

下表为拟新增/复用的配置含义，名称和数值均为提案，不是已接受的运行时YAML字段。

实施按可归因的三阶段推进：固定图诊断→入口质量/成本准入→目标总容量调度；每阶段冻结前一阶段版本，避免同步更换搜索预算、回源算法、图大小和线程数。若固定图无法通过质量，则先修复搜索路径/预算分配，不用份额调节掩盖该问题。

实验验收同时看零失败与预算/去重正确性、整体和分流群体配对Recall、成功QPS、p99、每查询各节点CPU、目标runnable与接纳/报告队列；显著吞吐收益初步以可重复≥5%为目标，报告跨重复区间，不承诺具体加速比。增大线程或降低召回取得的收益不能算本机制收益。

先验证固定到达率下源排队下降、目标不出现更坏拥堵，再检验闭环容量是否增加，最后用200K自然回放30分钟确认成本、流量份额和回收稳态。主报告绘制QPS/质量/源与目标排队、成本分解、份额与预测误差，标明控制决策时间。

未来实际执行时同问题一轮仅一条TestLog；本次仅设计，不新增性能日志。实现与实验结果记入Research，具体机制验证通过后再写入DESIGN并标局部解决。

## 八档收敛后的快速验证计划

2026-11-04，R001/F02/F05/F07/F10/F23，设计讨论，非新实验。用户要求下一步将负载均衡转化为QPS收益。本节细化实施顺序，不修改运行时默认、不启动测试、不宣布问题解决。依据：[八档综合复核](../test/entry_expected_work_sweep_20261104/FINDINGS.md)、[报告](../test/entry_expected_work_sweep_20261104/REPORT.md)、[TestLog](../TestLog.md#entry_expected_work_sweep_20261104)。

### 已知问题与待证假设

- 固定同一α≈0.3副本、份额0.9，T80仅接全局3.128%流量；源展开/全局请求88.671→84.557（−4.64%），源/目标ready均值98.72/9.75ms。过滤后有效搬走的工作不足。
- 全部入口开放、份额0.9，接流20.550%，源展开降至66.298（−25.23%）；源/目标ready均值2.49/87.12ms，QPS19628.90。该副本确实能分担源工作，但高份额把压力转移给目标，且质量尚未配对验证。
- 无副本前后基线20750.69→19701.88QPS，漂移−5.05%，而T80相对前基线仅+1.23%。本轮不能认定稳定吞吐增益，也不能按80→10的顺序结果选最优点。
- 待证假设：先保持较广入口覆盖、减少分流份额，再排除低收益入口，可能比“固定0.9后大量关闭入口”更有利。中间点不保证存在，回源和新增搜索/通信成本可能使所有份额都无收益。

### 第一小轮：只改变份额，快速判断是否存在收益区间

固定原200K查询及顺序、D200/beam11/C1536/每机64搜索线程、同一图和原生运行时哈希、暖缓存、RDMA传输且pull关闭。构建、退役、自动份额及入口关闭在本轮冻结；全部覆盖入口固定开放，因此这是固定目录性能消融，不声称在线入口收敛。测量期间仅原生采集，Python分析在测量结束后执行。

1. 预热并校验无副本基线A0；增加“图已加载、份额为0”对照A1，分离常驻图成本。候选都与邻近A1比较，最终收益还需对A0成立。
2. 首测全部覆盖入口、份额0.5。每个有效测量窗至少60秒且包含完整200K查询回放；预热和配置切换排空另计。观测源/目标runnable等待、ready分解、节点CPU-ms/全局请求、QPS和质量。
3. 若目标先拥堵，下一点0.3；若源仍明显拥堵且目标有余量，下一点0.7。两端均差则停止扩展份额网格，转入成本分解。0.3/0.5/0.7均为诊断点，不是默认建议。
4. 保留至多两个候选，交错A1—B—A1，并逆序/重复复验；至少三个独立运行对用于判断稳定收益，不把百万次重复请求当作百万个独立实验。原始时间窗和基线漂移一起报告，不用线性校正制造收益。
5. T80/份额0.9目录可复用本轮稳定快照作诊断参考，不重新跑八档学习。若新候选改善排队却仍不提高QPS，先检查目标服务成本、回源任务数、网络/顶层队列和客户端供给，避免继续扩大副本。

入口关闭的学习与冻结性能测量分别报告；不把低份额下尚未成熟的在线目录与稳定目录直接比较。路由份额指合格入口请求分往副本的概率，绝非全局请求占比。相同(query ID, occurrence, seed)使不同份额可形成一致的嵌套接流群体。

### 第二小轮：区分入口成本与入口收益

只有第一小轮找到有前景的份额后，才在该份额下比较T80与T120；若数据指向两者之间，再增加T100，不先跑完整阈值×份额网格。对候选目录各学习一次，冻结后交错测量；正式入选者再恢复在线策略验证保持和漂移。

每个实际分流query需要与无副本同query配对，至少记录源节点CPU节省、目标新增CPU、其他节点变化、实际回源后的CPU/展开、分支数与通信量，质量也按同query配对。当前S=P(回源)×E(剩余预算|回源)仍保留为成本信号；S不等于实际回源展开数，也没有表达该query原本在源上的工作量，不能独自决定收益排序。

若引入收益控制，先离线计算每条入口路径的全节点CPU成本向量，再最小化最高节点的“每请求服务需求/有效服务能力”，加上网络、内存和顶层容量约束。允许总CPU小幅增加换取瓶颈卸载，但不默认其一定合算；阈值和质量保护以外，不要求每个入口的回源率都降到最低。

### 第三阶段：将有效的静态点变成在线控制

第一、二小轮先证明稳定QPS收益；随后才实现/校验目标总容量控制。每秒采样，约每5秒后台更新不可变路由快照，小步增加份额、目标过载下调，使用滞回和健康窗口；所有指向同一物理目标的家族共享额度。源/目标待运行计算排队、pending工作和服务速率共同决定调整，区分区域串行/网络等待，CPU核当量仅作一项输入。

控制器只选择新query的入口目的地，不在搜索过程中提前触发远端扩展；回源仍由原边界扩展函数决定。每query仍只派发一个根搜索，统计走既有原生分片计数与后台汇总，不新增搜索热路径全局锁或同步探针。

### 验收与停止条件

- 成功QPS优先：目标是相对同期无副本基线可重复提升至少5%，跨独立运行的区间需支持正收益。小于漂移/不确定性的差异只记为未证明；≥5%是研究目标，不保证达到。
- 同时要求零失败、预算正确，整体与实际分流query群体的配对Recall损失分别不超过0.5个百分点。更换接流群体后重新匹配其无副本结果，不能用整体基线代替群体基线。此前使用过的数据只作开发验证，独立质量验收需另行固定未参与筛选的集合。
- 报告三节点实际工作和runnable/ready均值、p95、QPS时间曲线；源队列下降但目标成为新瓶颈不算完成。CPU成本与墙钟等待分开，不把分支时间相加当端到端时延。
- 若全开放低份额已不满足命中群体质量，先作诊断，不推广；若筛选后仍无收益，则先定位副本准备/重复估距、回源冷启动与重复工作、派发/报告成本，再决定改图或重新启用RDMA尾部拉取。
- 入选点再做约10分钟同负载保持检验，之后验证在线构建/退役；不把预建暖缓存结果冒充完整动态或冷SSD收益。
