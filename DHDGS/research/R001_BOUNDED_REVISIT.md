# R001：可重访搜索、入口质量与在线复制（2026-10-26）

本轮实施说明，性能结论见 [完整实验报告](../test/replica_revisit_20261026/REPORT.md)。关联 R001、R005、R010。此前 §44 的“物理节点单次访问”不适用于部分副本；新模式替代该限制。历史配置仍可重放。协议修复已验证，紧凑副本的质量保持和有效负载均衡仍未验收；配置默认关闭负载均衡。

## 1. 身份与正确性边界

- 查询保持一个 `query_request_id`；每次访问有独立 `branch_id`。记录和重传去重按二者共同索引。同一分支的报文必须一致；新分支允许回到旧物理节点。
- 路径仍记录真实物理节点，可出现 `A→B→A`。分支祖先ID不能重复，分支槽位不能凭重访恢复。
- 每个分支仍最多派发一个子分支。派发时切出预算：`本地已用 + 本地未用 + 子预算 = 本分支预算`，对子树递归验证；全查询最多200次展开。父分支继续本地工作，完成后释放计算线程，并独立报告给顶层。
- 心跳与取消按查询更新该节点上的全部分支。父报告、子报告乱序到达时，顶层以分支树和预算等待，不以“物理节点数”判断完成。
- `seen` 区分已经展开与仅发现过的顶点。传给子分支的是祖先已展开集合和实际携带的前沿；不能把父节点丢弃的所有未展开候选永久列为已搜索。
- 新版本增加本物理节点的查询共享展开表：容量由查询总预算预分配，64位ID用原子CAS插入，无计算线程阻塞锁、无扩容。返回该节点的分支跳过已经被本查询领取的顶点，统计 `duplicate_local_expansions_avoided`。这是本机精确去重；不同机器上的副本仍可能并行展开相同ID，必须报告 `duplicate_expansions`，不能宣称全局完全去重。

## 2. 跨节点间隔

`peer.allow_node_revisit` 开启重访；`peer.min_expansions_after_cross=N` 控制间隔。第一次进入原始分片不设间隔；跨机到达的分支、以及直接进入部分副本的根分支，在实际成功展开 N 个顶点前优先保留本地计算。批次数、估距次数和等待时间不计数，max-wait 强制规则也不能绕过间隔。

若本地候选耗尽，`peer.cross_on_local_exhaustion=true` 允许提前跨出并记录 `cross_dwell_exhaustion_escapes`；设为 false 则该分支停止并报告 `minimum_local_expansions_unmet`。严格模式可能再次截断搜索，不能作为召回保证。

原有收益/开销函数保持作用。`scheduler.remote_weight` 控制远端相对倾向，本轮从1降至0.25；实际概率还依赖候选收益、通信估计、温度与强制条件，0.25不代表固定25%概率。跨机间隔和总预算共同限制重访链，不能单凭“允许重访”宣称ANN精确。

## 3. 有界切图及入口质量

在线采样按原始HNSW入口汇总实际源节点展开集合和CPU；按每组记录承担的工作量排序选择入口组，受 `max_core_rows` 约束。在源节点添加有限halo：按来自已选顶点的入边次数排序补入源节点本地邻居，受 `halo_hops` 与 `max_region_rows` 约束。保留原始全邻接和全部估距依赖，不把图剪成丢失出口的闭合小图。

硬容量限制同时检查实际全部文件字节、量化依赖字节、目标空闲空间预留，以及 `max_target_shard_fraction × 目标原始分片字节`。超限则拒绝；不通过静默截断记录来满足容量。

在源节点构建时计算有界随机游走驻留先验。令 S 是复制记录集合，原始出度为 deg(u)，第 t 步仍位于 S 的概率为 s_t(u)：

```text
s_0(u) = 1
s_(t+1)(u) = sum{s_t(v) : (u,v)为原始边且v在S内} / max(deg(u),1)
r_H(u) = [s_0(u)+...+s_(H-1)(u)] / H
w(u) = floor + (1-floor) × r_H(u)^power
p_replica(u) = controller_fraction × w(u)
```

越靠近出边界的入口，驻留先验通常越低；中心入口通常越高。这不是欧氏“离质心距离”，也不是实际ANN展开数的理论保证。实际搜索按距离选择邻居，必须用探测及全量结果验证。路由只保存合格HNSW入口的一个权重；不在每次HNSW查询中做图遍历。数据节点只保存最多 `max_peer_entries` 个跨节点副本入口映射。

## 4. 在线门控与快速发布

负载观察使用每窗搜索线程CPU增量除以 `窗口时长 × 工作线程数` 得到利用率；当前积压估计为 `queued × 最近平均服务时间 / workers`。来源压力取当前积压和已完成任务等待p95上界的较大值。摘要必须新鲜；来源利用率/等待超过阈值、目标利用率/当前积压低于阈值、利用率差足够大，同一来源/目标对连续满足 `sustained_windows` 次，且没有构建中/活动区域、冷却已结束，才提交选区。没有足够独立入口观察时记 `NO_CANDIDATE` 并等待，不造热点查询。

本轮最终设置：每100ms读取负载、200ms评估控制、持续3窗；来源利用率至少0.15且等待至少2ms，目标利用率至多0.75且当前积压估计至多16ms，利用率差至少0.08；摘要期限1200ms。这些是为了观察短200K自然流内的反应而使用的实验阈值，不是通用最优阈值，也没有调低搜索预算。

保留独立真值校准模式；本轮自然负载实验使用 `validation_mode=shadow`：从已经观察到的无标签查询中取有上限的探测集，重放原始入口与强制副本入口。它检查 top-k 一致性、源CPU净节省、目标新增CPU和实际驻留展开数，不读取测试真值。

第一版整区门控在200K自然流中拒绝了两个小副本。随后改为逐入口门控：满足最少探测数、一致性、驻留及净卸载条件的入口才可发布；未被探测或不合格入口保持原始路由。合格探测总数仍须达到下限。低样本门控仅是实验性防护，不等于独立召回证据。最终200K召回率全部离线计算，控制器不消费真值。

当前影子驻留指标取根分支本地总 `work_spent`，可能包含目标原片工作，并非严格副本内首次出区距离。首次跨机前展开数保存在 `fork_events.local_expansions_before`，副本记录读取量另记；后续质量门控需要按进入状态与顶点归属结合这些信息，而不能把本地总工作量解释为子图质量保证。

源节点切图→独立RDMA维护通道传输→目标校验/预热→探测→入口发布，均在正式计时期间进行。后台发布不可直接产生搜索分支：只有边界选择函数已经批准远端搜索后，才查询副本位置目录，决定原分片还是副本作为执行位置。目录TTL过期自动使用原始位置。

目标副本已撤下时，只能在明确收到“任务未接纳”的响应后，保持同一分支ID和预算改派原始节点。父清单预先声明允许的回退节点，顶层验证实际报告路径。ACK丢失或一般网络异常不允许另起一份任务。

目标退让独立使用 `target_queue_limit_ms` 和**当前积压**；过去完成任务的p95保留为诊断。已空闲的目标不能仅因历史p95高于来源触发阈值就持续将分流比例减半。目标利用率超过 `target_util_limit` 或当前积压超过目标阈值时减半；否则按校准的源CPU节省/目标CPU增加、入口到达率和目标余量计算容量上限，单步增加受 `fraction_step` 与 `max_fraction` 限制。最终案实际0.5→0.6→0.7→0.75，入口权重还会进一步降低单入口实际概率。

所有候选/探测和目录都有数量界：最终核心4096、总记录8192、全部文件256MiB、量化依赖128MiB、最多32条影子探测、peer目录8192项、目标原片字节比例0.1。实际副本约129.16MiB。文件校验及预热发生后才进入门控；“结构READY”不是可接流条件。容量不足、质量不合格、超时均保留失败版本记录，不发布入口。

## 5. 本轮采集及限制

生命周期计数：切图尝试/完成、复制尝试/完成、READY、发布、失败、回收，并保留每个版本的阶段时间、字节数和原因。

每版本入口 `entry_selected` / `entry_completed`，跨机入口 `peer_selected` / `peer_completed`，对应展开工作量；选中不等于接纳，更不等于完成，失败与重试分别看报告和传输记录。最终成功查询的完成计数在顶层按分支报告去重；已创建却从未获得流量的版本也应列出零计数。

固定完整200K查询及顺序，原始负载不做热点筛选。记录检测到首次分流的时间、热点源/目标CPU及队列、每秒QPS、p99、召回、重复工作、提前跨出比例、复制开销和各版本流量。

当前控制器仍只管理一个活动/构建中的区域；多个不相邻热点、热点寿命短于复制时间、广泛结构性失衡，仍可能无法用一个小副本改善整体性能。不能以功能测试通过关闭R001；也不能只展示进入了副本的样例而省略全量请求的覆盖率和负收益。

## 6. 本轮验证结论与未解决项

七次测试每次完整200K不同查询、同顺序、64工作线程/数据节点、预算200、并发1024；无请求失败/超预算。最终回归58项，57通过、1项显式后端跳过。按查询和物理节点合并审计，启用共享展开表后没有本机重复展开；跨机器重复仍平均约6.34次/query。

最后一次8192记录副本检测至发布4.432秒，切图/复制各1次，入口选择与完成32次，peer选择与完成448次，涉及478条查询。全部版本（包括零命中版本）见 [区域表](../test/replica_revisit_20261026/regions.csv)。节点仍有55.19/43.62/29.02搜索CPU核当量的差异，副本覆盖仅0.239%，不能宣称均衡完成。

最终QPS15563.26、p99179.03ms、全量Recall96.989%。但478条命中查询配对无副本基线Recall为93.8703%，副本为93.5356%；9条下降、4条上升，配对差−0.335个百分点。低样本根入口影子一致性不能保护所有peer的部分状态。下一步必须单独校准peer前沿、剩余预算及祖先历史，验证有流量权重的驻留/回源预测，之后再扩展多区域覆盖；**不能将当前权重公式解释为已证明无损的子图质量算法**。

所有性能结果是共享机器上的热缓存单次测量，差异尚不能作稳定因果归因。设计已确认的是协议边界、计数与有界资源机制，R001与R010的整体研究目标保持开放。
