# R001-A24：完整 h 跳副本的回源削减

2026-10-30，本轮实现及实验完成。关联 R001/R005/R008/R010；下文区分已实现机制、限定实验结果和未验收研究方向，R001整体仍开放。按用户要求，入口几何切图封存为未来研究，保留 A23 的代码与证据。

## 问题与验收

A23 的 H 命中约 27.73%，首次派发前平均展开 35.81 点，之后源侧平均展开 131.20 点；几乎全部命中仍回源。源进程占核下降约 8.73%，QPS 中位 9401。不能将副本命中率当净卸载率，亦不能假设剩余工作已经很少。

本轮先用既有轨迹统计回源时授权、后续源实际展开、CPU、读取字节与批次；再分别检验图扩展和远程数据拉取，最后测组合。目标是约 95% Recall 下提高整体 QPS、降低固定到达率下的源整进程 CPU；同时报告目标负载、总 CPU、网络、尾延迟和失败。

## 路径一：完整核心及预算内连接扩展

保留已验证的完整 h 跳核心，以完整的一跳球作为扩展单元。扩展只能从已包含的有向边界附着；保存核心证书、每个附着球及成员摘要，独立验证所有原始邻接，不能把裁剪 BFS 当完整局域。容量计入记录、邻居 RaBitQ 依赖、成员与证书，不只统计向量。

研究局部 PageRank、锚定局部流割、预算覆盖的适用条件。候选效用综合历史源尾部工作覆盖、PPR 局部性与边界保留；历史只用于估计权重，完整邻域用于避免仅复制历史轨迹的孔洞。全查询覆盖包含 AND 条件，不据此声称次模或贪心近似保证。固定总包容量比较，也单列从旧 H 原样扩充所增加的容量，避免把更多存储冒充算法收益。

## 路径二：有界远程拉取后在副本计算

只有现有跨区域扩展函数批准访问源区域后才允许拉取，I/O 调度器不自行决定扩展。按剩余授权、批次数/字节上限和实测源计算/网络成本选择拉取或原回源。保留 epoch、实际展开去重、全局预算和区域所有权；失败时仅未消耗预算/未展开候选可回源，不能重置搜索。

RDMA READ 读取注册内存，不能直接读取 SSD。须区分一侧 READ、RDMA 消息式批读与文件预热/注册开销，不把源读取、打包 CPU 隐去。原始记录之外必须供应后续邻居的量化码和归属。记录每次拉取 RTT/排队/源读取/打包/字节、实际计算位置、剩余授权和退回原因。

### 已实现的预算闭包割

令完整核心为 R。每轮只考虑原始有向出边可达的边界锚点 a，每个候选块为源片内完整一跳球 B(a)。不改图边，不补造捷径。原始 H 的完整核心和 PPR 扩展保留；本轮新增评分本身是一次边界扩散，并非完整 PPR 求解。

历史工作权重 w(v) 来自独立历史查询的源侧真实展开，按每请求源 CPU 均分到展开记录，并适当提高后段权重。用于本轮固定副本的离线比较；通用在线接口没有尾部历史时使用入口权重。不能把两者的成本和泛化效果混为一谈。

每轮在有界候选池计算：

```text
b(a) = sum over original edges u->a with u in R:
       [(1-eta)/|R| + eta*w(u)/sum_v w(v)] / out_degree(u)
```

令 m(v) 是候选池中包含新增记录 v 的球数，给锚点的代理奖励为：

```text
p(a) = b(a) + eta * sum over v in B(a) outside R:
       w(v) / [m(v) * sum_x w(x)]
```

除以 m(v) 防止多个候选对同一个历史记录重复认领完整奖励；这会低估只选其中一个球的真实覆盖，因此只是可解释的保守线性代理，不是查询覆盖的精确模型。所有 p 在每轮归一化。

构造有向依赖图：源点到锚点容量 p(a)，锚点到所需新增记录为不可切依赖，记录到所有新增邻居量化码为不可切依赖，记录/码到汇点容量为其字节成本乘 λ。已有核心依赖已支付，共享记录和共享码只计一次。最小割求解固定候选池、固定 λ 下：

```text
maximize over selected anchors A:
sum_{a in A} p(a) - lambda * C(R union all B(a), a in A)
```

通过价格扫描和二分保留满足记录、码、总字节三项硬上限的最佳已验证结果。该过程不保证找到硬预算问题的全局最优解，也不声称最大化真实 Recall；多约束和离散大小可能留下未用容量。候选数、轮数、割次数、边扫描、邻接缓存和规划墙钟均设置停止阈值；工作空间按容器估算，不等价于进程RSS硬隔离，墙钟采用合作式检查，不是硬实时期限。完整核心证书、附着球列表和摘要计入容量预留，发布时仍以实际包为准。

### 已实现的有界批读与回退

跨节点扩展函数先批准源区域动作。只有该副本授权的剩余额度不超过 `peer.replica_pull.max_remaining`，且轮数和字节预算允许时，才以批读代替该次计算派发。此处是该区域当前授权的剩余额度，不能称作仍在其他分支手中的查询全局剩余额度。

源节点在查询级接纳保护下检查 epoch、执行配置签名、令牌、批次上限及源执行器状态。已有源执行器、已宣布pending/opened的源区域或其他副本的保留权时拒绝拉取；否则保留该副本的源首次启动权。数据请求只读取不可变向量/原邻接与邻居 RaBitQ 码、中心和归属，不消耗搜索授权，不在源执行距离计算。副本取得完整依赖后按原流程计算，才消耗其原有授权和本机实际展开去重额度。

本轮使用已有原生 RDMA 收发线程处理网络；需要数据的搜索线程休眠等待，其他工作线程可继续计算。休眠仍占用一个搜索工作槽，尚未实现协作恢复到其他查询。它不是一个查询多线程搜索，也没有由 I/O 调度器提前扩展远端。源读/打包仍占接收处理资源，必须用源整进程 CPU 校验净卸载，不能只报告搜索线程节省。

每个授权内按 `max_rounds`、`max_bytes`、`batch_records`、`batch_bytes` 设限。拒绝、传输失败或上限达到后，转回已有派发路径，携带真实已展开 ID 和未消费授权；不会重置预算。数据读可重试但当前失败即保守回退，避免额外反复往返。报告记录拉取次数/字节/等待、源读和打包 CPU、实际在副本计算的点数及回退原因。

额外的 `peer.replica_source_min_expansions` 只约束副本向原源节点提前派发；本地候选耗尽仍允许回源，其他数据节点遵从原函数。它属于搜索策略消融，需要同图同召回校验，不能用高停留阈值隐藏缺失目标或把减少回源本身当作成功。

尚未实现或验收：单边内存注册/READ、冷 SSD 下独立读队列/异步恢复、跨授权复用拉取缓存、基于实时目标队列和网络拥塞的成本预测。当前静态门槛先通过实验标定；后续成本模型应比较“实测源 CPU 节省”与“源读打包 CPU + 副本占用 + 网络轮数”，不能仅依据剩余额度断言划算。

### 成本模型和边界

候选球和量化依赖形成的闭包网络有 V 个顶点、E 条依赖边。本实现采用一般容量的 Dinic；一般最坏界为 O(V²E)，浮点容量还需容差处理，不能据此声称每次规划接近线性。工程上限制候选数、轮数、边扫描、工作空间及规划墙钟；保留上一轮完整可行解。证书重放扫描实际核心与附着球的原始邻接，和规划分开计时。本轮最大候选配置为每轮1024、最多6轮、12次价格二分、1GiB邻接/流工作空间预算，实际主区5120个候选、44次割。

远程拉取的延迟近似为 `批数 * 往返等待 + 传输字节 / 有效带宽 + 副本计算`；源CPU成本包含读/依赖收集/打包/网络协议。真实可卸载量应该比较源整进程占核，而不是只比较距离函数。受搜索依赖约束，后继记录往往要等当前批邻接到达才能选择，不能用带宽上限推断已消除串行往返。本轮只对批准动作的已知候选合批，不跨越用户限定的扩展决定。

若源是唯一瓶颈，单位请求源CPU需求下降可以提高容量；但目标节点CPU、收发池、内存带宽或远程等待成为瓶颈后，该比例只是上界估计。批读的最终验收因此同时要求整体QPS和固定到达率源占核，计算回源率只用于解释。

## 本轮结果与后续取舍

2026-10-30，R001-A24（`hop_return_20261030`）实现及本轮测量完成，**R001整体仍开放**。以完整h跳为主力，几何方案封存为未来研究。五方法、两负载、三次重复、每次200K，共600万主对照请求；另有校验及尾部包络筛选。

完整球预算闭包扩图F保留原87入口、主区域49,670→77,003记录，同容量H/F实际包约1071MiB。饱和QPS中位 10164→10850（+6.74%）；同6000QPS源整进程占核 39.47→37.51（-4.96%），数据节点最大/平均负载 1.717→1.680。相对小容量H0的QPS +11.09%、源占核 -11.86%，含容量及停留变化，不能全算选图收益。各自命中请求的源展开约 112.96→79.59，仍有 95.65% 计算回源；共同入口/同请求结果另列，不能混用命中群体。

消息式RDMA批读FP把计算回源降到 55.39%，但相对F的QPS -6.56%、同到达率源整进程占核 +3.84%，未通过吞吐/净卸载验收，保留可选且默认关闭。它不是一侧READ；源接收处理线程仍pread、收集依赖和打包。阈值64指当前区域剩余授权，8轮、每批8记录/512KiB、总4MiB；96/128加大包络的20K探索单列，不能替代确认。源访问（搜索或读）不能与计算回源等同。

全部600万主对照无查询失败、无预算超额、重复区域执行或同机重复展开；各轮整体及自身命中Recall均≥95%。暖缓存、共享机、tmpfs捕获、受控稳定热点；200K次出现含42,898个不同测试ID，非真实未来漂移。API入口/merge慢轮保留，不能将所有QPS波动归因批读。扩图+校验90.57s起自预建核心；部署计时与其分开，不冒充实测在线全周期。通用在线接口已接入扩图，但本轮历史尾部权重未自动接入热点控制器，缺省使用入口先验，尚不能保证复现同样图和收益。

全量用冻结source_v2；交付源码另加核心行数防御和已宣布pending/opened源区域拒绝拉取的保护，只做正确性回归，不冒充已测二进制。推荐继续验证F；先优化拉取的重复码传输/源打包，再研究一侧READ和冷SSD异步服务。完整证据见[报告](../test/hop_return_20261030/REPORT.md)、[审计](../test/hop_return_20261030/audit_final.json)、[研究推导](R001_HOP_RETURN_REDUCTION.md)、[已实现机制](../DESIGN.md#hop-return-reduction)和[TestLog](../TestLog.md)。

## R001-A25：开放历史入口的源容量曲线（本轮已完成，R001开放）

用户要求将总副本包上限改为源分片 FILES 字节数的0.1～0.9，逐档比较H、HP、F、FP；确认“完整核心＋外层完整一跳球截断”，并开放新覆盖的历史热门入口。本轮沿用原完整核心与三个小区域，固定256个历史热点候选池；新增入口独立检查完整源内一跳邻域，不只判断入口点是否落入包中。

H按原有向图边、按广度接纳附着完整球；F先做既有预算闭包选球。在10%和90%试构建中，原F仅使用约86.81%/84.01%的预算，故正式F依次细化候选粒度4096→1024→256，再用完整球广度补齐；两部分行数和成本分别保留。所有方法都保留完整核心，超限球整体跳过，按记录及共享量化依赖增量核算，最终独立重放证书并检验真实包字节。不能把补齐称为闭包全局最优；跳过的球也不保证实现精确背包填满。

## R001-A26：联合选择容量、接流份额与拉取门槛（2026-10-31，实验中）

单独最小化计算回源不等于提高系统容量。用 `c_i(α,p,τ)` 表示每个完成请求在节点 i 上消耗的进程 CPU 秒，另外用 `s_i` 表示搜索工作槽的占用秒。消息式 RDMA 拉取会减少源搜索，但增加源读和打包、目标计算，以及等待返回期间的目标工作槽占用。线程休眠不消耗同量 CPU，却仍可能限制吞吐，所以两种资源均需测量。

容量与接流优化先固定禁用拉取。对相邻份额 p 的实测单位请求成本作局部线性插值，可以估计源与目标何时互换瓶颈；预测只用于提出下一组参数，必须实测确认。异构主机的64逻辑工作线程不是64个等速物理核，也不能把各机器占核相同当成严格均衡。报告同时保留原始占核、队列、工作槽占用与QPS。目标是约95%质量约束下尽可能高的QPS，并在近似等吞吐方案中比较回源和物理容量；不以降低请求量制造源CPU改善。

拉取只发生在既有边扩展函数批准源动作后。令 `b` 为该区域当时尚未消费的授权，静态门槛为 `b ≤ τ`，其余轮数和字节硬界保持不变。若 `b > τ`，立即沿现有计算派发路径处理；不能等待本地再消耗预算来强迫达到门槛，这会改变搜索策略。候选阈值先粗扫，再围绕真实首次批准动作的预算峰值细化。

经济上需要比较同一查询群体下“源搜索CPU减少”与“源批读服务CPU增加”，并观察目标额外CPU、串行往返及占槽是否压低QPS。将收益只除以实际拉取的请求会产生选择偏差；同时报告全部请求、全部副本命中和拉取子群。源访问率包括读服务，不冒称拉取消除了源访问。小门槛若几乎不触发，只能说明适用请求少，不是低成本的正收益证据。

已有A25非拉取记录的首次派发额度集中于39：例如F α=.6有19,063/27,145次直接源派发在39，≤32仅1.96%，≤48为74.07%。这来自既有授权和批次行为，不是新性能结论，亦不假定其他份额/查询群体相同。本轮按实测分布追加39附近门槛。粗扫/细化使用原校验ID，200K确认使用原测试ID；原测试已复用，不作为未知未来流量。参数、CPU放置、选择规则、阶段证据见[本轮方案](../test/hop_tuning_20261031/PLAN.md)。尚无本轮验收结论，不改写既有默认和研究状态。

### A26 的入口归属修正与参数选择口径（校验阶段）

入口重绑定不按测试query修改图；输入是冻结历史入口池、现有成员及原始邻接。令旧小区域入口集合为 E_s，大区域为 R：

```text
Safe(R) = { e in historical_entries : e in R and N_source_out(e) subset_of R }
E_large_new = E_large_old union Safe(R)
if every entry of an old small region is in E_large_new:
    remove that region from the next prebuilt portfolio
otherwise:
    retain the old region (do not publish conflicting partial mappings)
```

核心与附着球证书保持原样；重新验证新增入口的源内完整一跳、所有成员可从核心到达、epoch、容量和成员摘要。成员不增大，依然保留真正的外部边界；新增入口元数据计入预留。`promote_covered_entries` 是可选YAML开关，单区和多区建图接口在扩图后调用同一验证函数，多区必须用扩图后的入口更新 `used_entries`。已有运行副本的无缝重绑定/退休没有在本轮在线验证；本轮在发布前构成新组合。

实际结构核验：811395条主区记录完全不变，5个入口全部通过；三个旧小区可以从新预建组合移除。重绑定加完整独立重放用时61.59秒，不能称为常数时间目录操作；这包含扫描大图核验的成本。新增/旧入口在留出流上的召回和回源仍须用后续检索实验判断。

接流参数采用局部成本拟合提出候选，而不由CPU占用的绝对数直接指定：

```text
c_i = process_CPU_seconds_on_node_i / completed_queries
A_i = observed CPU capacity proxy for node i under the same placement
s_i = occupied search-slot seconds per completed query
QPS_bound ~= min_i( A_i / c_i, worker_slots_i / s_i )
gap(p) = c_source(p)/A_source - c_target(p)/A_target
p_next = quantize_and_clip( p_lo - gap_lo*(p_hi-p_lo)/(gap_hi-gap_lo) )
```

预测须实测；只有两个端点、非线性缓存/队列、异构CPU、共享机器和网络均会使它失准。先修正p，再在质量与预算约束下选α；本轮近最高3%是实验权衡规则，不是数学最优性或统计非劣界限。

RDMA门控保持 `approved_source_action AND remaining_credit <= tau AND round/byte_limits AND no_conflicting_source_executor`。阈值拒绝即按原扩展算法派发，不人为等到更小预算；源读服务CPU、目标工作槽占用及实际通信同时计量。小阈值几乎不触发时，不得由其单轮高QPS宣称批读有效。
