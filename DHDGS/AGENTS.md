# DHDGS 实验收尾规则

用户要求：围绕同一个问题开展的一轮实验（可包含多次独立测试）在本目录 `TestLog.md` 中只保留一条汇总记录，此要求适用于后续所有实验任务。

- 实验开始前明确目的、待验证假设、期望效果、配置与对照；使用 `tools/experiment_log.py` 的 `experiment()` 包裹实验启动、测量及清理，记录 Asia/Shanghai 墙钟起止时间。日志写入必须在测量热路径之外。
- 按要验证或解决的问题划分轮次，不按每个配置、重试、回归或单次运行拆分主日志。同轮共用稳定的 `round_id`，同一条主日志可在开始、分析、收尾时原位更新。新的研究问题另建轮次。
- 单次测试仍使用独立 `id` 与输出目录，但元数据指定所属 `round_id`；调用日志工具时若 `id != round_id`，只保存本地证据，不写入主日志。重生成报告不得重新追加子测试条目。
- 每轮结束必须在一条汇总中登记：时间、目的/问题、假设、期望效果、固定配置、各次测试改变的变量及取值/对照（`variables`）、实际代码改动（未改代码则明确注明）、源码版本/哈希证据、关键结果和限制、报告及图表链接、下一步建议。失败、中断、重试和负面结果在汇总中说明，详细时间和证据留在各次测试目录。禁止把期望写成观测结论。
- 数据采集结束先记录“测量结束，待分析”；生成报告和图表后补齐结果，核对所有产物链接，再改为“已完成”。没有图表或代码变更时注明原因，不留空。不得在报告尚未完成时将实验视为已完整交付。
- 实验脚本必须接入上述日志工具，或在同等收尾路径显式更新日志；新脚本参考 `test/EXPERIMENT_WORKFLOW.md`。不要依赖对话记忆。
- 异常退出后检查运行中记录并补记。SIGKILL、断电无法执行 finally，恢复后必须根据证据登记中断；不虚构结束时间。历史补记明确说明缺失时间，不能把日志写入时间当作测试发生时间。
- 日志不得包含认证信息。清理实验目录时保留 `TestLog.md`；产物已删除/迁移要在对应条目说明，不制造失效证据。
- 性能结论需保留计时口径、失败数、召回率、热/冷缓存和样本量等限制。提交给用户的实验报告必须附日志位置。
