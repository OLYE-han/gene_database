## 维护流程：问题 → 尝试 → 验证 → 设计

- **Research.md**：按问题保存证据、候选方法、成功/失败/未完成的尝试、结论边界与下一步。每个问题使用稳定ID（R001等）；尝试使用局部ID（R001-A01等），不得删除失败记录或重复利用旧ID。问题归并时保留既有ID、尝试ID及锚点，通过父问题字段和标题层级表示从属关系；父问题与子问题分别验收。
- **[TestLog.md](TestLog.md)**：按实验轮次记录真实时间、变量、源码/配置、报告和图表。一轮包含多个独立测试时仍只写一条主日志；Research中的多项引用不能产生多条相同轮次日志。
- **[DESIGN.md](DESIGN.md)**：收录已验证可行的方法及其适用条件、实现、参数和限制。文献设想、待证实机制和未完成实验留在本文件。DESIGN已有历史提案不自动成为已验收设计。
- **[test/](test/)**：保存每轮YAML、源码/二进制哈希、原始指标、失败证据、报告和图表。后续清理必须同步修改证据位置，保留台账与结论，不制造失效链接。

开始新工作前，先找到相关问题并明确本次假设、对照、预算及验收条件；新问题先登记。实验元数据可带 `research_ids: [R001, R002]`，并在 `purpose` 与报告中明确关联。现有 [experiment_log.py](tools/experiment_log.py) 会保留附加元数据，但不会自动判断研究结论或替人更新本台账。

每轮分析完成后，在对应问题下追加一条尝试记录，列出各独立测试改变的变量与结果链接。**实验轮次“已完成”只表示采集、分析和报告完成，不表示研究问题已解决。** 同一研究问题可以经历多轮实验；同一轮的补测、失败重试更新该轮原日志。

验证可行时，在同一次收尾中完成：补齐证据 → 将最终方法及限制写入DESIGN并回链研究ID → 将具体问题或优化标记“已解决”，填写解决日期与DESIGN位置。若仅解决一个子问题，只关闭对应优化条目，主问题继续保持“部分验证/研究中”。出现反例或回归时标记“重新打开”，保留原结论及适用范围。实验流程见 [EXPERIMENT_WORKFLOW.md](test/EXPERIMENT_WORKFLOW.md)，执行规则见 [AGENTS.md](AGENTS.md)。

| 状态 | 含义 |
|---|---|
| 待验证 | 已明确问题或假设，尚无足以支持方案的实验 |
| 研究中 | 正在定位、设计或进行实验，不代表持续有进程运行 |

### 热点子图复制与入口分流（R001主线）

#### 问题与证据

Intel-31每分支计算排队在512/1024/2048并发下分别约15.60/51.76/142.99 ms，搜索CPU核当量约57–58；Intel-30同期约35–38。数据量均衡不等于查询工作量均衡，继续增加并发主要放大热点队列。[逐节点证据](test/concurrency_best_20261023/per_node.csv)。

现有 [search_loop.hpp](cpp/search_loop.hpp) 的归属选择优先本地，否则选择尚可访问的较小节点ID；现有边界副本尚未充分用于按目标节点排队调节工作分配。用户提出：从A选择繁忙子图复制到较空闲B，顶层知晓副本，对合适的查询改变入口。

#### 候选方法与待验证假设

**选择复制内容。** 统计查询群体、实际展开/候选依赖、估距与精排工作、逻辑读取及热度持续性。优先按服务工作量而非请求数/入口频次选热点；顶点成本不含排队时间。采样、线程内聚合、重频项统计的开销必须有对照，不为每次展开新增全局热点锁。

以 `h(v) = 观察窗口内归属于v的CPU工作量 / 窗口时长` 作为热度候选，以 `Cover(q,R) = 查询q在区域R内的CPU工作 / 查询q总CPU工作` 筛选副本。工作量归属可以先按批次近似，但须注明估计方法。覆盖率不等于本地完成概率，更不等于召回保证。

**形成子图。** 从目标查询群体的热点核心出发，用实际候选发现/展开关系补充必要邻域；按副本字节预算或边际收益停止。比较固定几跳、几何划分、访问加权图割与查询工作集合超图。普通图的最小割不一定最适合beam search；顶点复制收益可能具有组合性，不能未经证明宣称简单贪心具有近似保证。

第一版保持A原图不变，复制原邻接关系；副本由核心、必要邻域及保留的区域外出口组成。不能递归复制全部邻居直到“闭合”，否则可能膨胀为整片。复制需包含相应向量、量化码/因子/中心或旋转参数依赖、邻接和定位信息；统计所有额外字节，不只计原向量。

**选择入口。** 入口ID只作筛选，还要识别副本适用的查询区域。预测目标的接纳等待、计算排队、搜索/I/O、通信及回源成本；不要把所有相关流量瞬间切到B。负载摘要可随现有心跳传播，不为每条查询新增状态探测RPC。分流比例受B的预计CPU/I/O/内存余量约束，渐进调整以避免同时涌向空闲节点。

**触发与回收。** 快层路由使用已有可服务副本，慢层创建/回收副本。只有持续拥塞、可迁移热点、目标余量和预计回本条件同时满足才复制；比较热点寿命与检测、复制、预热及回本时长。采用滞回、冷却、最短保留时间和复制资源预算；初始阈值必须作为实验变量，不写成已知最优常数。

#### 必须保持的语义与风险

- “入口改道比例”不能代替卸载收益。回源A、重复搜索、维护工作及B服务成本都要计入；出现A负载不降、全局工作上升时保留负结果。
- 原先按物理节点禁止重复访问。B承载A副本后可能出现 `B副本 → A剩余区域 → B原分片候选`，旧规则会丢弃后续候选。用户指出此限制后，R001-A06已改为按分支身份接纳、允许有界物理重访并约束跨机间隔；见 [DESIGN §45](DESIGN.md#bounded-revisit)。协议修复不等于有限预算ANN召回得到保证。
- 顶层目录与B本地定位必须共同认识副本；只更新入口映射、却沿用不认识副本的本地owner解析不足以工作。原始全局ID和图版本保留，副本目录使用独立版本；注意目录容量及每候选查找成本。
- 发布流程为 `复制中 → 校验 → 预热 → 可路由 → 停止接新查询 → 排空 → 回收`。查询固定版本，迟到报告/失败/取消/回收均不得破坏预算、去重与报告合并。
- 网络调度只执行扩展函数已经批准的跨节点动作；副本预热和I/O完成事件不得擅自增加查询分支。父分支本地结束后仍立即释放计算资源，不等待子分支。
- “热副本”不是自动具备故障恢复能力的持久副本。第一版不据此宣称高可用或在线更新一致性。

#### 实验顺序与验收

1. **机会分析**：采样搜索工作集合，画出副本容量—实际可卸载CPU工作—回源概率曲线，并估计热点寿命。历史回放仅筛选候选；复制改变物理位置和搜索路径后仍须实际查询验证。
2. **静态副本对照**：无复制；容量允许时的整分片副本；固定小逻辑分片；按访问频率选点；查询工作集合驱动的部分子图。固定每物理节点搜索线程及总资源，防止用额外工作池冒充算法收益。
3. **路由消融**：静态分流、仅负载、仅查询匹配、查询匹配＋负载＋回源代价。保持质量/预算一致；跨系统基线则各自在相同质量与资源下调参。
4. **动态验证**：稳定偏斜、突发、移动热点、热点寿命短/近/长于副本生效时间。测量复制期间退化，不只展示预热完成后的成绩。

必报：源节点CPU/排队净减少量、目标增量、总估距/精排/扩展工作、入口副本命中、本地完成比例、回源概率与工作、复制/预热字节及耗时、RAM/SSD副本空间、反应/收敛时间、振荡和副本浪费、QPS/p99/召回/失败。按相同额外空间给出Pareto曲线；若整片或固定小片已经达到相同收益，要说明复杂切图的必要性不足。

“已解决”需明确所覆盖的热点/资源/访问语义范围，证明独立查询上质量与正确性不退化、源节点工作实际转移、端到端或SLO有效吞吐有可重复收益，且动态维护成本可接受；单次入口改道成功不能关闭本问题。

## R003：真实SSD压力、读放大与分级读取

**状态：待验证；优先级：P1；解决日期：未解决。**

**证据。** 当前2560维float32向量约10 KB，节点记录约12 KB；邻接与完整向量一起读取。最近200万查询的物理读取累计仅335,872字节。关闭应用缓存、调用pread或使用io_uring都不意味着绕过OS页缓存。[数据格式/I/O设计](DESIGN.md) §6.2–6.14；[实测限制](test/concurrency_best_20261023/REPORT.md)。

**候选方向。** 先用受控进程/缓存内存预算验证设备I/O，再比较原记录布局与邻接/向量分离、量化信息分级细化、相邻区间合并、跨查询在途读取复用。保持“只读取搜索函数已经选定的本地候选”；I/O调度不能提前扩展远端。现有异步独立提交与真正减少读取字节是不同功能。

**实验与验收。** 暖缓存和内存受限负载分开；核验应用逻辑读、进程物理读、设备IOPS/带宽/队列与缓存预算。顺序比较同步、异步独立提交、在途复用、连续合并和布局变更，保持搜索工作或质量可比。缓冲预约、取消迟到完成、错误、版本pin和公平性正确；确认新路径在真实SSD压力下减少读放大或端到端代价。不得全局清空共享机器缓存冒充可控对照，亦不得将设备缓存命中称为NAND实测。
