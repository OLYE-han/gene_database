# DHDGS 实验验证与共同决策清单

初稿日期：2026-10-15；进度更新：2026-10-16。状态：E02 输入抽查与 E03–E05 小样本几何预实验已启动，尚无 ANN 召回或性能结论。

已知条件：200M×2560 维未归一化 ESM2_3B 向量、200K 查询、4 台约 1 TB RAM 的服务器；目标采用高召回 ANN，第一质量门槛为平均 Recall@10≥0.99；允许备用路由入口并记录开销。

更新：当前数据为正在传输的 2M 轻量子集，实际根目录 `Data/seq_2M/seq_2M`，具有 200K 库内查询、cosine 与 euclidean 两套排除自身的 top-100 标签；200M 保留为后续较大规模验证，长期目标更新为百亿。已完成的文件头、ID 哈希和少量距离核对见 [DATA_INSPECTION.md](DATA_INSPECTION.md)，仅属于 E02 的部分输入检查，不是完整实验结果。

本文配套 [DESIGN.md](DESIGN.md)。设计中的几何分片、归一化尺度、RaBitQ 位数、扩展收益函数、等待补偿和布局均为候选方案。不能因已写入设计就将其视为验证成立。

## 1. 执行与决策约定

1. 先完成正确性检查，再比较性能。错误实现、漏边、错用 ground truth、提前结束等问题直接修复，不以性能收益抵消。
2. 实现候选方案时保留可切换配置、简单基线和观测指标。正常进行已授权的可逆开发与实验，不为每个小实验重复申请确认。
3. 在距离语义、分片方法、量化/SSD 内核、分布式调度四个决策点提交实测证据，与用户共同选定最终方案；实验探索配置不自动变成默认配置。
4. 报告收益、代价、失败工作点和统计不确定性。没有明显差异时报告“证据不足”，优先讨论是否保留简单方案，不宣称复杂方案胜出。
5. 所有大规模运行先从小规模验证正确性并估算资源。本文列的是验证项目，不意味着现在启动全量索引构建或四机基准。

## 2. 共同实验规范

### 数据与质量

- 核对生成脚本、实际池化、向量类型/范数、重复 ID、零向量、非有限值、查询是否来自库内。原始数据保持不变。
- 固定数据/查询 ID 清单、训练与校准划分、随机种子、索引版本及源码版本。校准集与最终测试集隔离，不能反复用最终测试集选参数。
- 以各自度量空间的精确 top-k 为 ground truth；cosine 与原始 L2 标签分开。平方 L2 与欧氏距离排序一致，但返回数值单位必须明确。
- 明确排除查询自身 ID 的规则；不同 ID 的相同向量不擅自排除。定义距离并列规则和评测中的等价结果处理。
- 平均 Recall@10 定义为逐查询 `|returned_ids ∩ truth_ids|/10` 的平均值，去重后计数；它不是“每条查询至少有 99% 召回”。返回不足 10 项不得改变分母。
- 报告逐查询召回分布和困难查询分组，防止平均值掩盖失败群体。超时/失败同时报告完成率及服务层质量，不能只保留成功请求而隐藏故障。

### 公平对照与测量

- 方法比较同时提供固定资源/工作量和固定质量的结果。核心性能结论以达到 Recall@10≥0.99 的工作点为主；相同 beam 参数不等于相同召回或相同工作量。
- 分片方法比较固定实际 RF 或总索引空间；量化方法比较固定内存字节数，并补充各自调优到相同召回的曲线。
- 单项消融固定同一图、查询、编码与缓存条件；改变 metric 或图构建参数时必须重建相关索引，不能称为只改了调度。
- 每个重点性能工作点建议至少 5 次独立计时运行；在可承担的规模上用至少 3 个构建 seed 检查随机性。全量重建次数根据小规模方差和资源测量共同决定，不能把同一索引重复查询当作构建 seed 稳定性。
- 报告均值、区间和原始分布。召回可按查询 bootstrap，延迟按独立运行或时间块分析；若同源查询相关，额外按已知家族/簇分组分析，不能假定所有请求独立。
- 记录 offered load、completed QPS、错误率、队列增长及 p50/p95/p99；同时做固定并发和开环到达率测试，说明发压端测量起点，避免遗漏排队时间。
- 未确定延迟 SLO 前，报告可持续负载及 QPS–p99 曲线，不以不断积压队列的瞬时 QPS 宣称“最大吞吐”。
- 分别记录每进程 RSS、页缓存/受控内存预算、I/O 读取字节与实际缓存命中。记录 CPU、NUMA、SSD、网络、线程/进程数、编译选项、SIMD 后端及后台负载。

## 3. 验证项目

### E01：检索距离与 ESM 向量语义（P0，决策点 A）

- **问题**：归一化是否丢失有用的模长信息，cosine 是否适合目标生物学检索任务？
- **对照**：原始平方 L2；归一化后的平方 L2/cosine。分析范数与序列长度、已有生物学标签之间的关系。
- **观察**：两种精确 top-k 的重合度、范数分布、有标签时的同源性/功能等任务指标、后续 ANN 质量成本曲线。
- **决策边界**：ANN Recall 只反映对所选距离的还原，不能证明生物学相关性。没有标签或既定任务定义时保留两套结果，与用户确定主指标；不宣称 cosine 已被证明更好。
- **当前数据补充**：2M 是已有 200M 的顺序前缀；需要检查其与更大样本的范数、密度、近邻距离和可用生物学分组分布差异。库内留一查询不能替代新查询分布的泛化验证。

### E02：ground truth 与评测正确性（P0，必过）

- **问题**：现有标签是否与实际 metric、归一化、查询 ID 和排除自身规则一致？分块 GPU 计算是否有数值偏差？
- **对照**：小规模直接 float64 距离与分块 BLAS/GPU 精确 top-k；多个数据块划分；单机与分片结果合并。
- **观察**：ID/距离一致性、边界并列、取消误差、重复向量、自身排除、分块合并正确性。
- **通过条件**：可解释数值误差之外的标签差异清零或修正；未经验证的标签不得用于性能结论。先测算全量 ground truth 的运行成本。
- **当前进度**：已抽查每种标签的前 64 行，并各重算 64 个已到达邻居的距离；未验证完整 top-k 正确性或全部传输完整性。小于 2M 的前缀实验需独立重算对应库的标签，不能过滤现有全库 top-100 代替。

### E03：采样、聚类与路由样本代表性（P1）

- **问题**：固定比例随机样本能否代表 200M 数据，N=4 个中心是否造成明显容量偏斜？
- **对照**：多个采样比例与 seed、普通 k-means 不同初始化；采用 cosine 时可比较欧氏 k-means 与球面 k-means，明确两者不同。
- **观察**：聚类目标、分片大小最大/平均值、空簇/退化中心、边界分数稳定性、路由命中、路由内存与构建时间。
- **决策**：选最小但稳定的样本规模与聚类方式。若偏斜严重，先报告证据；虚拟分片或容量约束聚类作为待讨论扩展，不自动扩大到负载均衡研究。

### E04：向量归属函数与尺度定义（P1，决策点 B）

- **问题**：几何边界裕量是否优于更简单的距离比较？簇尺度归一化是否真的有用？
- **对照**：唯一最近中心；固定最近两个中心；相对平方距离差；未归一化的超平面距离 h；本文 γ=h/s；s 使用 RMS 半径或稳健半径。随机平滑复制仅作为可选对照，不是必选实现。
- **观察**：相同实际 RF/空间下的分片间真实近邻覆盖、跨片边与可达性、达到相同召回的访问量、RPC、QPS、p99。
- **决策**：几何解释不能代替收益证据；若简单方法相当或更好，向用户建议采用简单方案。

### E05：重叠比例、上限和校准（P1，决策点 B）

- **问题**：ρ 是否可控，副本上限 2 或 3 哪个更合算，样本阈值是否迁移到全量？
- **对照**：ρ 初始扫描 0/0.05/0.1/0.2/0.3；C_max=2/3；样本分位数与全量标量阈值校准。
- **观察**：实际多归属比例、RF、各片容量、分位点并列与重尾、多重边界点比例、构建通信、质量与查询开销。
- **正确性**：主归属唯一、归属集合随阈值单调、RF 界、并列处理、N=1、空/近重合中心。高 ρ 会覆盖内部点，必须报告边界厚度而非始终称为“窄边界复制”。
- **决策**：共同选择冗余预算及阈值校准方式，不只按最高召回选择最大 ρ。

### E06：边界边合并、桥接与可导航性（P1/P3）

- **问题**：局部建图后的边并集是否足以连接分片？受保护桥边的数量和选择能否降低跳数？
- **对照**：无额外桥边（诊断基线）；连通性修复的双向生成树；增加少量近邻分片桥；完整边并集与带分片覆盖约束的剪枝（后者可后置）。
- **观察**：SCC/入口可达性、边界度数、每片门户覆盖、串行跨机跳数、图扩展深度、召回、索引字节与访问成本。
- **通过条件**：修复版本的可达性通过实际图遍历验证，所有副本邻接表一致。连通性通过不等于少跳；若少跳不成立，如实报告。

### E07：Vamana 建图与局部搜索预算（P2）

- **问题**：图度 R、构建 L、RobustPrune 参数、搜索 L、SSD beam 如何影响高维数据的质量和成本？
- **对照**：固定精确构建距离，对关键参数做分阶段粗到细扫描；构建使用量化距离仅作为后续可选实验。
- **观察**：构建时间/峰值内存、度分布、图页读取、候选数、串行深度、精排数、Recall–QPS–延迟。
- **决策**：选高召回下的合理图与搜索预算，避免用巨大搜索预算掩盖图结构问题。

### E08：RaBitQ 位数、量化质量与 PQ 基线（P2，决策点 C）

- **问题**：2560 维下 RaBitQ 是否在目标内存预算和高召回下具有实际优势？
- **对照**：RaBitQ 1/2/4/8 bit、PQ 合理码长、精确距离导航的小规模参照；比较固定编码字节与各自最佳高召回配置。
- **观察**：全局与近邻区域的估距偏差/误差分位数、排名翻转、CPU 时间、实际编码及元数据内存、精排 I/O、最终召回。
- **决策**：不能只看平均估距误差或单次 SIMD 吞吐；以完整搜索达到 0.99 的综合成本选位数，并保留不利结果。

### E09：RaBitQ 中心与旋转（P2，决策点 C）

- **问题**：共享主中心编码是否比零中心或分片各自编码更合算？结构化旋转的实际质量如何？
- **对照**：零/全局中心、主归属中心、每副本本地中心；FHT/Kac 与小规模稠密随机正交旋转参照；多个旋转 seed。
- **观察**：估距误差、近邻排序、编码时间、查询预处理、跨片可比性、码缓存量与副本编码开销。
- **通过条件**：旋转状态保存/加载一致、零残差和维度布局正确。不同编码中心的副本不得误用 query state；统一逻辑向量的排序规则必须明确。
- **决策**：共享编码与局部精度之间的取舍由数据确定，不把快速结构化旋转当作严格均匀随机旋转证明的直接替代。

### E10：估距内核与图访问模式（P2）

- **问题**：逐候选 core、批量评分和 FastScan 在不规则图邻居访问下谁更快？
- **对照**：相同编码精度与评分语义，比较逐点 SIMD、批量 gather、适用的 FastScan；包含真实候选批次及尾批。
- **观察**：端到端估距时间、gather/打包成本、缓存命中、不同 ISA 和线程数、估距结果一致性。
- **决策**：微基准提升必须能反映到图搜索；若 FastScan 搬运开销抵消收益，使用较简单的 core 路径。

### E11：SSD 布局与读取策略（P2，决策点 C）

- **问题**：10 KiB 原向量是否使多扇区节点读取产生不可接受的放大？
- **对照**：原向量+基础邻接表多扇区记录；邻接表与原向量分离；不同 SSD beam、缓存和预取策略。分离布局若改变距离细化时机，需单独说明并重新匹配召回。
- **观察**：真实读取页数/字节、IOPS、队列深度、缓存命中、精排读取、p99、磁盘空间与写入构建成本。
- **决策**：在自然缓存和受限内存两种环境下选布局，不能只在原向量已缓存时评估 SSD 设计。

### E12：HNSW 入口与备用路由（P3）

- **问题**：样本最近邻能否提供好的数据图入口，何时启用备用入口最合适？
- **对照**：固定中心/medoid 入口参照；样本 HNSW 不同样本量与 efSearch；备用入口开/关和不同停滞触发；少量多入口用于研究对照。
- **观察**：路由耗时/内存、首入口到近邻的扩展成本、备用触发率、额外入口数、RPC/SSD、召回和尾延迟。
- **决策**：已确认允许备用入口，但触发阈值尚未确定；不能因允许备用入口而默认首跳广播全部四台。

### E13：跨机扩展选择函数（P4，决策点 D）

- **问题**：U=G/C 的复杂调度是否优于简单策略？点距离是否能有效预测扩展收益？
- **对照**：立即远端扩展；仅按距离全局优先；固定本地优先+定时发送；收益/成本策略。对 κσ、η、等待权重、成本项逐项关闭消融。
- **观察**：相同图和同召回下的 RPC、字节、SSD、QPS、p99、候选等待及截断量；候选评分与后续 top-k 改善/新区域发现的关联。
- **验证方式**：小规模冻结候选前沿，分别执行竞争动作测量即时收益；端到端配对实验判断最终收益。即时 top-k 改善不能覆盖桥接点的延迟收益。
- **决策**：没有显著收益的项可删除。等待补偿不取代硬性公平发送；乐观距离分数不得当作确定性剪枝界。

### E14：批大小、等待上限与成本模型（P4，决策点 D）

- **问题**：如何避免为凑批损害 p99？远端时延与 I/O 模型能否正确排序动作？
- **对照**：固定批大小/定时器；自适应批大小；固定成本、EWMA 成本及带远端队列信息的模型。覆盖低负载、接近饱和、不同 RTT/带宽和缓存条件。
- **观察**：预测/实测动作时间误差、动作排序错误、批次填充、等待时间、请求字节、饥饿次数、整体质量成本。
- **决策**：单看 RPC 减少不算成功；需核算等待带来的延迟和远端拥塞。网络扰动仅在隔离测试环境实施，不修改共享网络配置。

### E15：查询状态传递、异步与远端编码缓存（P3/P4）

- **问题**：局部 continuation 相比完整状态迁移有多少收益？并行是否带来大量重复工作？远端编码值得缓存多少？
- **对照**：小规模完整状态迁移参照、查询 token+增量；串行继续与有界异步；无/有限远端码缓存；必要时比较简单二进制 TCP 与 gRPC 的端到端成本。
- **观察**：序列化时间、字节、query/visited 状态内存、重复扩展、在途数量、缓存成本、协调节点 CPU 与瓶颈。
- **决策**：先测已选传输实现的成本；只有证据表明 RPC 框架成为瓶颈时才投入替换，避免为了微基准扩张实现范围。

### E16：精排与终止预算（P2/P4）

- **问题**：精排过早或过多是否浪费 SSD？搜索停止规则是否会过早放弃远端近邻？
- **对照**：不同候选精排数、立即/批量精排、全局节点/I/O 预算、固定与停滞相关停止规则；概率误差引导的精排作为显式近似对照。
- **观察**：真实距离计算数、读取字节、Recall、未发送/在途/截断任务数、少于 k 个结果的情况。
- **通过条件**：输出距离按承诺精排，终止不漏合并在途响应；预算不足与正常收敛区分。精排不能被描述为恢复了未访问的真近邻。

### E17：缓存、内存预算与并发资源（P2/P5）

- **问题**：每台 1 TB RAM 是否掩盖 SSD 行为？线程、I/O 深度与并发查询如何争用资源？
- **对照**：自然缓存、明确内存预算、冷启动/稳态；不同图/向量/编码缓存分配；合理线程、NUMA 与在途 I/O 配置。
- **观察**：RSS/页缓存、实际盘读、CPU/SSD 利用率、队列、QPS、p99、错误和内存峰值。
- **决策**：分别给出内存充足和受限场景结论；不把 mmap 文件称作已经验证的磁盘检索，不在共享主机上随意清理全局缓存。

2026-10-16 线程专项：用户明确选择“优先最低 p99，再比较 QPS”。固定索引、量化、搜索预算、BLAS 线程和观测开销，交叉扫描 `peer.worker_threads` 与客户端并发的 1/2/4/8/16/32 档位；每档独立重启并随机顺序重复。按固定并发分别选择满足 Recall@10≥0.99、无失败的最低 p99 配置，冻结后在互不重叠的查询集上与 4 线程基线比较，并延长请求窗口复验。不得将不同客户端并发的结果当作线程数的单因素对照；也不能将线程池容量视为实际忙碌线程数。详细方案、选择规则和运行记录位于 [线程实验目录](test/worker_threads_20261016T233213/PLAN.md)。

### E18：构建规模、shuffle 与索引发布（P1/P3/P5）

- **问题**：全量构建是否受 RAM、临时磁盘或单路由节点限制？一次主要向量 shuffle 的真实成本多大？
- **对照**：分块大小、流式背压、并行度、可恢复检查点；采样统计、shuffle、建图、边合并分别计时。
- **观察**：峰值 RAM/临时盘、传输字节、各片长尾、重复传输、总构建时间、发布前完整性检查。
- **通过条件**：ID/位置一致、manifest 原子发布、构建中断可检测或恢复；不能把元数据通信和边同步漏记为“只通信一次”。
- **百亿专项**：无需先拥有百亿向量即可测试跨越 2^32 的稀疏全局 ID、64 位序列化和偏移、局部 ID 上限、外存批次计数、超过缓存预算时的背压；这些是规模边界正确性，不冒充百亿性能验证。

### E19：分布式正确性与异常场景（P3/P4，必过）

- **问题**：副本去重、边登记、超时重试与终止是否造成漏搜、循环或重复计数？
- **对照**：同一全局图的单进程确定性模拟器与多进程 reference_order；注入延迟、乱序、重复响应、连接中断、版本不一致。
- **观察**：候选/结果及固定轮次一致性、边界副本邻接一致性、预算守恒、查询状态回收、失败可见性。
- **通过条件**：正确性问题解决后才进入性能比较；网络异常不返回伪造的成功空结果。此项不意味着第一版承诺服务器故障后的高可用。

### E20：端到端收益、交互作用和四机扩展（P5）

- **问题**：局部优化组合后是否仍有收益？200M 规模是否仍满足目标？
- **对照**：随机分片全节点查询、聚类独立 DiskANN、多副本固定方案、完整 DHDGS；在可容纳的规模做 1/2/4 节点强扩展及每节点等数据量的弱扩展。
- **观察**：Recall–QPS–p99–空间曲线、构建成本、每机资源与负载偏斜、跨机串行跳数及分布。
- **交互实验**：ρ×搜索预算，bit 数×精排数，SSD 布局×缓存预算，batch 等待×并发/RTT，备用入口×调度策略。先做少量有依据的组合，不做全参数笛卡尔积。
- **决策**：以达到质量门槛的 Pareto 工作点共同选择默认配置；无法同时取得最高召回、最高 QPS 和最低 p99 时明确取舍。容量不允许单机装下全量时不强行伪造单机全量对照。
- **长期规模**：在 2M/更大实测结果之上建立包含副本、边界码、页对齐和元数据的百亿容量/通信模型，验证不同节点数的可行性；区分“预测”和“实测”。实际百亿验证需相应数据和硬件，未取得前不宣称已支持百亿性能。

## 4. 顺序、规模与交流节点

| 顺序 | 项目 | 实验规模与目的 | 共同决定 |
| --- | --- | --- | --- |
| A | E01–E02 | 真实向量样本和可精确核对的数据；核实语义、标签 | metric、ground truth 与评测契约 |
| B | E03–E06 | 合成退化数据+保留 2560 维的真实子集，逐步增加到百万/千万级 | 分片函数、尺度、ρ/RF 预算、桥接策略 |
| C | E07–E11、E16–E17 的单机部分 | 真实 SSD，既有缓存内测试，也有工作集超过受控 RAM 的测试 | RaBitQ 位数/编码、图参数、SSD 布局 |
| D | E12–E15、E18–E19 | 先独立进程真实 RPC 验证，再到真实多机；多进程不替代多机性能 | 入口策略、调度函数、批处理和全局预算 |
| E | E17–E20 | 候选配置通过前面筛选后再运行 200M/4 台最终评测 | 默认工作点、已验证适用范围与后续研究问题 |

实际子集与阶段用量根据数据路径、硬件和初步时间测量确定。缩小 M 时保留真实 D=2560；随机低维合成数据仅用于正确性，不能代表真实质量或性能。局部缓存、网络与候选分布会随规模变化，小规模胜出配置必须在目标规模复核。

## 5. 每次交流的结果格式

每个实验使用固定编号，提交以下内容后共同决定：

1. **验证问题与候选方法**：本次到底改变了什么，其他条件如何固定。
2. **运行证据**：配置、数据/查询清单、源码版本、硬件、seed、原始结果路径和实际运行次数。
3. **结果**：质量门槛是否达到、收益/代价曲线、区间、失败与异常。
4. **解释边界**：是否只有微基准收益，是否依赖缓存/特定负载，有无未解决混杂因素。
5. **建议与备选**：保留、修改、放弃或补充实验的理由；不以“理论上应当更好”替代实测。
6. **共同决策记录**：用户选择、依据、适用条件、尚未解决问题。未讨论的配置标记为探索配置。

当前 E02 完成文件长度、查询 ID 哈希及 128 行标签抽查，尚未验证全量 checksum 或完整精确 top-k。E03–E05 已运行多 seed 小样本几何预实验。第二阶段完成真实 RaBitQ、HNSW、Vamana 图、磁盘记录和三个独立进程 TCP 的正确性测试，并对 4096 条真实向量、16 条官方查询进行一次端到端子集评估；没有基于这些查询调整参数。结果见 [PHASE2_RESULTS.md](PHASE2_RESULTS.md)。这不代表 E06–E19 的公平性能对照已经完成。

所有开放参数由 [configs/dhdgs.yaml](configs/dhdgs.yaml) 提供，每次运行保存配置快照。下一批实验应优先验证：

1. 备用入口开/关及停滞阈值：当前小样本触发频繁，需在独立校准集比较同召回下的扩展量与跨片访问。
2. 同一图上的 reference/adaptive/local_first：匹配召回、预算和缓存条件，再比较批次数、等待及 p95/p99。
3. 相同目标实际 RF 的分片对照、位数与量化误差覆盖率；误差尺度目前只作启发式，不能用作确定性剪枝。
4. 逐级扩大索引和查询集，记录内存、ghost code 开销、最终度数与构建时间；当前内存构建器不直接扩到百亿规模。
5. 真实三机通信成本与缓存控制下的 SSD 测量。回环进程测试不替代网络实验，文件 pread 计数不替代物理 I/O。

正式选择参数前仍按上面的 A–D 决策流程交流；默认 YAML 是探索配置。
