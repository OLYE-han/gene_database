# Intel-35 内存结果暂存与独立报告程序

保持数据节点检索、预算和扩展算法不变。原生顶层增加不展开Python对象树的完整结果包接口；Intel-35用有界memfd保存结果包和时间戳，内存足够时全部查询结束后才执行JSON转换、召回计算和报告。超过内存上限时由独立程序批量处理并生成JSON分片；不设无限后台队列，背压单独计时。

正确性验证覆盖：原生/普通API兼容、时间戳保留、无提前JSON写入、完整分片、独立处理进程、容量上限、单记录超限、处理失败原始数据保留、全量回归。

性能对照使用上轮同一原生数据节点部署及全量seq_2M索引，Intel-35顶层代码分别选择上轮冻结版本和当前版本。三机每节点32计算线程、客户端并发256、预算200，预热32，固定2000验证查询重复5次构成每轮10000。两个头部版本都用C++搜索与原生控制；差异是结果捕获与报告路径。新模块只需部署在Intel-35；数据节点运行已验证的相同冻结代码，不混入远端重新编译差异。

端口30751–30753及30810，与220xx常驻服务隔离。每案例保存完整YAML、头部源码摘要和原始结果。测试按先旧再新的顺序单轮执行，不作长期稳定性或统计显著性承诺。原生API完成、压测观察和暂存完成时间均保留；比较同口径API完成延迟，并保留旧consumer-inclusive延迟，不把改时钟边界当作性能提升。

最终方案进一步将MessagePack编码后移：主暂存区保留C++原生对象，按保守对象占用计费，默认4GiB；排空时才编码至memfd并交给独立程序。中间编码包方案与最终结果分别保留，不覆盖已有实验。另用8MiB本地2000查询验证容量排空。
