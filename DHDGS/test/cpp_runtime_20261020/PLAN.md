# 在线查询路径迁移至C++

将数据节点的协议解析、身份/额度接纳、工作线程池、子分支构造和派发迁移为原生代码；将顶层的入口路由、心跳/结果接收、分支校验、top-k合并迁移为原生代码。Python保留YAML、索引加载编排、管理事务和离线分析；已有路径保持可用。

所有C++工作线程仅持有原生数据，禁止查询途中回调Python；每分支由一个计算线程完成，本地候选耗尽或预算耗尽后释放计算线程，网络确认由独立控制器继续处理。远程查询仍只能由扩展选择函数授权，最多单次前向且禁止重访。

复用现有RaBitQ/HNSW及C++图搜索算法，提取无Python API的共享搜索核心；保留Python适配器作回归。保持PCG64随机序列、预算/槽位守恒、token/epoch/revision校验、幂等重试和取消语义。状态表和有界工作队列采用短临界区，不宣称无锁。

配置开关集中到configs/dhdgs.yaml。管理RPC仍支持停流修改参数并保留索引。原生网络和完成路径需有故障注入测试；先验证逐结果/预算/分支等价，再进行同负载三机对照。测试结果保存于本目录，不改变常驻集群。

完整结果采用流式归档，避免压测客户端长期持有整个Python对象图；基线和候选采用同一记录方法作公平对照，保留用户关心的全部指标，客户端提交至消费与原生内部完成时间分开报告。不能把后台完成时刻冒充用户收到结果的时刻。

迁移不以提高搜索预算或减少指标换取QPS，不保证迁移自然达到等待100ms。完成后报告实际范围、兼容性、性能和尚存限制。
