# 原生搜索循环与 95% 召回预算

每个数据节点上每个查询分支固定在一个计算线程内执行；线程间并行的是不同查询。I/O 线程或 reactor 只提交读取、管理缓冲与完成通知，不扩展候选。保留由决定函数批准的远端分支与父节点继续本地搜索语义。

将候选、邻居、精排、RaBitQ 查询预计算/估距、预算、fallback、远端决定移入释放 GIL 的 C++ 热循环。Python 保留协议、生命周期、I/O 提交适配和最终报告构造边界。复用节点内聚合 I/O，不因 I/O 调度派发远端搜索。

首先校验与 Python 对照的计算结果和预算/单次访问约束，再验证同步/聚合 I/O、多查询多核与线程归属。目标改为平均 Recall@10 >= 0.95；现有 128 条校准样本中预算128/frontier64召回0.952344，仅用于缩小范围，需独立验证新实现。热页缓存与物理 SSD 性能继续分开，不宣称未实现的 O_DIRECT 已启用。
