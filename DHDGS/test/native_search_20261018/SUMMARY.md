# C++ 完整搜索循环：完整 2M 索引验证

范围：Intel-35 单机、三个独立 TCP 数据进程；完整 2,000,000 × 2560 索引，原始 L2、RaBitQ。buffered I/O，OS 缓存不清空。不是三台物理机器的新版本性能结果。

每分支一个固定计算线程；不同查询并行。Python 仍负责协议和聚合 I/O 边界。Native 不在候选/距离循环中运行 Python。

## 当前选择与运行

推荐热缓存配置为 [recommended_sync.yaml](recommended_sync.yaml)，native / 8线程 / 预算192 / frontier64 / 同步读取；[pipeline_uring.yaml](pipeline_uring.yaml) 提供相同预算的跨查询聚合读取。两份均是本机三个TCP数据进程的完整参数文件，索引通过符号链接复用，无需重建。默认项目配置也更新为native、8线程、192/64、目标0.95。

在 DHDGS 目录执行 `.venv/bin/python test/native_search_20261018/run_config.py --config test/native_search_20261018/pipeline_uring.yaml`，脚本管理三个TCP服务并复用已验证的全库真值和冻结验证查询；同步对照将配置改为recommended_sync.yaml。两种配置共用端口，分开运行。新记录写入相应配置输出目录的runs中，不覆盖历史。普通CLI benchmark会重新全库精确扫描计算真值；全量2M复验建议使用本脚本。
