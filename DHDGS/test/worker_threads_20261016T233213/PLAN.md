# 数据节点工作线程数实验

用户选择：**优先最低 p99，然后比较 QPS**。截至启动时，运行代码和生产默认 YAML 均未修改；仅创建实验脚本及配置。

## 研究问题与选择规则

在固定客户端并发度下，增加每个数据节点的 `peer.worker_threads` 是否降低查询 p99？客户端并发与数据节点线程数是独立变量。每个并发档位先要求两次校准均无失败且平均 Recall@10≥0.99，然后按合并请求的 p99 最小选配置；完全相同的 p99 才按总体 QPS 较高、线程较少依次选择。没有合格配置时明确标记，不放宽质量约束。

按并发档位分别冻结选择，用另一批查询比较所选值与现有 4 线程基线。验证失败或优势不能复现时不宣称找到稳定最优值，不在验证结果上再次调参。所有线程/并发档位的全局最优仅指本轮有限网格与负载，不能外推为生产最优。

## 固定条件与变量

- 三个独立数据进程，TCP loopback；线程数 1/2/4/8/16/32，客户端并发 1/2/4/8/16/32，共 36 个点。
- 每点两次独立服务重启，分别随机打乱顺序；各点依次执行，避免多组实验互相争用。
- 复用不可变 4096×2560 pilot 索引、L2、1 bit RaBitQ；`max_expansions=64`、`frontier_size=32`、`local_beam=4`、`remote_weight=1`，与旧实验的高召回工作点一致，质量仍以本轮实测为准。
- `max_active_queries=128`、BLAS/OMP 线程数 1，详细 trace 关闭，其他参数固定。线程池上限并不代表实际始终有那么多忙碌线程；并发低于线程数时多余线程可能不会启动。
- 校准使用新查询行 [2048,2176)，128 条；验证使用互不重叠的新查询行 [4096,4352)，256 条。精确真值针对索引中的 4096 条计算，排除自身；按 query 字节、排除 ID、数据身份和索引 ID 校验缓存。
- 每个客户端预热相同的前 4 条查询，预热不计时；高并发档位预热总次数更多，但查询 ID 集合相同。索引加载、真值计算、服务启动/清理不计入查询延迟。
- 应用缓存 16 MiB/数据节点，OS 缓存不清空。本实验是缓存友好的原型运行时实验，不能声称测得 SSD 冷读能力。
- 保持系统现有 CPU affinity，不强占共享服务器全部核心；记录主机、可见核心、负载、源码与索引哈希。不是独占机器实验。

## 观测与解释

逐 query 保存延迟、recall、网络字节/RPC、pread、CPU、扩展数与阶段分解；每点保存节点 CPU 核当量、内存、物理读字节与服务生命周期。已实现的指标中端到端 admission/server queue wait 仍未知，不从剩余延迟推断精确排队时间。阶段累计 CPU/pread 不能直接相加为端到端占比。

汇总 p50/p95/p99/均值/QPS/失败率/recall，给出逐 trial 变化和 query 聚类 bootstrap 的描述性区间；重复同一个 query 不当成独立新查询。校准单点仅 256 请求，p99 由极少数请求决定，因此必须保留独立验证和不确定性，不能把小幅差异称为稳定提升。闭环、有限请求窗口的 QPS 不等于固定到达率的稳定容量，后续需更大独立查询集与持续负载确认。

服务线程可能受 GIL、共享内存、控制回调和 CPU 调度影响。观察到线程越多越慢时先依据指标定位，不能直接认定 SSD 饱和或 GIL 为唯一原因。路由/客户端与数据进程共享本机资源，也是结果适用范围的一部分。

## 文件与复现

- `plan.yaml`：实验网格、查询范围和用户选择标准。
- `base.yaml`：固定配置；每次运行的完整配置在 `calibration/`、`validation/` 子目录。
- `provenance.json`、`harness_sha256.json`：产品源码、索引、实验工具的版本证据。
- `run_experiment.py`、`worker.py`：精确真值准备、随机扫描、冻结选择与验证。只在实验进程内复用真值，不修改产品搜索代码。
- `execution_logs/`：每次启动日志及返回码；失败启动和失败查询均保留。
- `selection_before_validation.json`：查看验证结果前的冻结选择。
- `runs/*`：原始 report、逐查询 CSV/JSONL、阶段均值、节点资源与服务停止记录。

运行入口：在 DHDGS 工程目录设置 `PYTHONPATH=python`，并将 `OPENBLAS_NUM_THREADS`、`OMP_NUM_THREADS`、`MKL_NUM_THREADS` 均设为 1，使用 `.venv/bin/python test/worker_threads_20261016T233213/run_experiment.py`。需要本机监听 TCP 权限；脚本只启动并清理其自身的数据服务。实验支持复用已完成运行继续执行，但会校验产品源码、索引版本和配置未变化。

## 较长窗口复验补充

在独立验证开始前记录 `confirmation_plan.yaml`：继续使用校准时冻结的候选与 4 线程基线，每配置两次服务重启，每次 256 个验证 query 各重复 4 次，共 2048 请求。该阶段增加尾延迟观测，不增加独立质量样本数，也不根据验证重新选择线程。初筛和短窗口结果仍全部保留，不能丢弃启动突发的慢请求。
