# 路由与入口派发对照

固定三机、每数据节点64查询线程、并发256、预算200、合并线程4、10000请求（同2000查询重复5次）、预热32、4GiB结果暂存。独立32751–32753/32810端口。

阶段A：路由线程4/8/16/16/8/4，顶层每目标连接上限32。阶段B：根据A选择路由线程数，仅将顶层connections_per_endpoint改为64/128，逆序重复；沿用A中对应路由的32连接基线。数据节点连接容量保持32。该参数同时影响顶层入口与心跳客户端，但两个客户端各自独立；不能称为仅增加入口线程。

原生入口网络客户端目前一个事件循环，没有可配置的客户端线程数。本轮先使用现有连接容量控制，结合queued→send_start和send_done→response_done度量验证等待，不将未测的事件循环延迟与连接池容量混淆。

采集QPS、p99、召回、路由/合并排队、入口RPC发送前排队/发送/响应等待、数据就绪与搜索CPU、进程负载、物理读。两轮短测限制显著性结论；全部资料保留在本目录。
