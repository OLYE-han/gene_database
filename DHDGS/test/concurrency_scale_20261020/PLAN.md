# 三机客户端并发扫描

固定每节点64搜索线程、顶层16路由线程/4合并线程/每目标32连接、预算200、预热32、每轮10000请求（同2000验证查询重复5次）。并发顺序256/512/1024/2048/2048/1024/512/256。仅修改客户端并发，保留最大活动查询2048与所有网络参数。

独立33751–33753、33810端口，不修改常驻服务。每轮结束后将本轮新产生的queries.part-*.json和report_context.json无损gzip压缩，解压校验SHA256后替换，保留archive_manifest.json；需要重新离线处理时先gzip -dk对应文件以恢复原名。已有历史实验不改动。压缩不进入查询计时。

比较QPS、p99、平均延迟、召回、失败、实际峰值在途、路由/数据就绪/网络排队、CPU负载和读开销。高并发与固定10000请求下存在启动和排空影响，不代表稳态容量。
