# 第二阶段：统一配置与端到端原型

日期：2026-10-16。实现已从几何工具推进到 HNSW → 分片图 → RaBitQ 候选估距 → 磁盘原向量精排的完整小规模链路。唯一运行配置是 [configs/dhdgs.yaml](configs/dhdgs.yaml)，命令及限制见 [README.md](README.md)。

## 实现内容

- 严格 YAML 配置校验、相对路径解析、可重新加载的配置快照与来源哈希；构建参数和索引不匹配时拒绝查询。搜索参数可在同一索引上重复实验。
- C++ 真实 RaBitQ core API、HNSW 和 Vamana 构建器；Python 负责分片归属、邻接并集、保护边、全局位置目录、磁盘文件、调度和实验。
- 重复顶点保存相同的合并邻接表；分片内双向环与中心 MST 桥接，全局强连通检查。连接性只保证可达，不保证有限预算召回。
- 三分片本地模式和持久 TCP 批量请求；uint64 全局 ID、epoch 校验、显式错误、全局扩展预算、在途请求等待及备用入口统计。
- 分块精确真值与逐查询评估报告。子集索引的真值针对实际索引行重算。

## 正确性检查

共 **27 项不同测试通过**：先运行含三进程 TCP 的 25 项完整测试，再新增并通过两项 CLI 流程测试，同时重跑原有 14 项核心测试。

覆盖内容包括：配置未知/缺失/重复字段、错误类型和重放；64/2560 维真实 RaBitQ、多位编码、零残差、旋转持久化；HNSW 大于 2^63 的 ID；Vamana 有效边与种子复现；L2/cosine 完整遍历与精确结果一致；副本边并集；预算限制、self 排除与去重；截断文件、错误 epoch；本地与三个独立 TCP 服务在有限预算及完整遍历下的参考搜索一致性。

TCP 测试在本机回环网络运行，已完成进程与协议验证，不能替代三台物理服务器性能测试。完整遍历达到精确结果是正确性测试，不是近似搜索性能成绩。

## 真实数据小规模试验

配置未依据以下查询结果调优。输入是 `seq_2M` 全库均匀抽取的 4096 条向量，维度 2560；原始平方 L2，三分片，ρ=0.1，RaBitQ 4 bit，Vamana 基础 R=24/L=64，frontier=256，全局扩展预算=256，adaptive 调度。

| 项目 | 实测结果 |
|---|---:|
| 唯一索引向量 | 4096 |
| 含副本的各片向量数 | 1373 / 1833 / 1351 |
| RF | 1.11255 |
| 实际多归属比例 | 11.1816% |
| 最大分片量 / 平均分片量 | 1.20671 |
| 建图时间 | 38.49 s |
| 查询数 | 16 |
| Recall@10，对 4096 条索引重算真值 | 1.0 |
| 每查询扩展量 | 256 |
| 平均端到端延迟 | 38.59 ms |
| p50 / p95 / p99 样本延迟 | 38.60 / 45.00 / 45.54 ms |
| 顺序查询速率 | 25.91 query/s |
| 备用入口触发比例 | 15/16 = 93.75% |
| 实际网络 RPC | 0，使用 local transport |

索引文件长度合计约 65.0 MiB，文件系统分配约 66 MiB。编码、原向量、邻接表、页对齐、位置目录及 HNSW 都计入索引目录；不能把 RF 直接当作总索引空间倍率。

该运行中 10/16 查询访问多个逻辑分片，其余只访问一个分片。每查询平均淘汰 713.75 个 frontier 候选，因此有限预算与队列裁剪仍是 ANN 的近似来源；这次没有出现召回损失不能视为普遍保证。备用入口触发频繁，需要开关对照来判断收益与额外开销，不能由触发率推断有必要或有害。

16 条查询取自官方查询文件第 0–15 行，数量小且不是随机抽取，结果仅作功能烟测。后续正式 held-out 集应排除这些已观察查询；原始 200K 查询尚未形成最终校准/测试划分。没有测量全 2M 索引的召回，也没有选择最终距离、ρ、位数或调度工作点。

延迟包含 Python 协调器开销和热缓存影响。顺序速率不是饱和 QPS；16 个样本的 p99 不具备稳定的尾延迟解释。读取使用 buffered pread，计数不代表物理 SSD 操作。
